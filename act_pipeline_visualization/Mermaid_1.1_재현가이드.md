# Mermaid 1.1 파이프라인 시각화 재현 가이드

- 기준일: 2026-11-03
- 함께 사용할 파일: [Mermaid_1.1_예시.html](Mermaid_1.1_예시.html)
- 목적: 다른 프로젝트의 구조와 처리 흐름을 같은 양식으로 설명하는 단일 HTML 제작.
- 예시는 PKG B 가족행사 심사 프로젝트. **배치·표현 규칙을 재사용하고 데이터·규칙·파일 경로는 새 프로젝트의 실제 내용으로 교체.**
- 이 예시는 **Mermaid 노드 + JavaScript/SVG 고정 배치** 조합. Mermaid 코드만 붙여 넣으면 같은 구간×Layer 정렬이 자동으로 만들어지는 것은 아님.

## 1. 완성본의 범위

- 1.1 방식 하나만 제공. 다른 도구 비교 탭·자동 배치 비교·재생 기능 없음.
- 상단: 프로젝트 목적, 데이터 출처, 조절 가능한 파라미터, 적용/초기화.
- 메인: 왼쪽 단계 설명 / 가운데 파이프라인 / 오른쪽 요구사항·입력 제약·요약.
- 하단: 같은 레이아웃의 영역 설명도, 사용 도구 설명.
- HTML 한 파일로 오프라인 열람. CSS·JavaScript·도형 라이브러리·내장 데이터·참고 이미지 포함.
- 다른 프로젝트에 없는 계층·DB·조건 분기·화면·반복을 억지로 추가하지 않음.

## 2. 메인 레이아웃

| 위치 | 표시할 내용 | 동작 |
|---|---|---|
| 상단 | 프로젝트 목적, 구조/적용 상태, 내장 데이터 출처, 입력 파라미터 | 입력값을 바꾸는 것과 적용을 구분 |
| 왼쪽 | Layer, 단계 제목, 입력, 출력, 목적, 진행사항, 관련 파일, 참고 화면, 개별 판단, 코드·근거 | 선택한 노드에 따라 갱신 |
| 가운데 | 가로 업무 구간 × 세로 Layer, 역할별 도형·색, 연결 화살표 | 노드 클릭·상세 보기·확대 |
| 오른쪽 | README 기준 과제 조건, 데이터 형식·제약, 저장 구조, 결과 요약 | 구조 상태에서는 변수, 적용 후에는 계산 결과 |
| 아래 설명도 | 실제 데이터 대신 각 영역의 목적·표시 도구 설명 | 위 메인과 같은 3열 배치 |
| 맨 아래 도구 설명 | 노드·화살표·연결 예시, 지원 범위, 처음 설치하는 방법 | Mermaid와 직접 작성한 기능 구분 |

- 데스크톱 예시: 왼쪽 약 300px, 오른쪽 약 240px, 가운데 나머지 너비.
- 좌우 경계 드래그로 너비 조절. 키보드 방향키·초기화도 제공.
- 사이드바는 자체 스크롤. 중앙 파이프라인의 높이를 충분히 확보.
- 작은 화면은 세로 배치하거나 도식 확대·스크롤 지원. 글씨를 무조건 작게 줄여 끼워 넣지 않음.
- ‘아래 영역 설명 보기’ 버튼은 넣지 않음. 하단 내용은 스크롤로 접근.

## 3. 프로젝트 구조를 읽는 세 기준

### 가로: 큰 업무 구간

- PKG B 예시: ① 입력 준비·검증·저장 → ② 사용자 실행·분석 → ③ 결과 보존·활용.
- 새 프로젝트에서는 실제 처리 목적에 맞게 구간 이름·개수 변경.
- 같은 구간에 속하는 관련 노드를 세로로 모음. **구간 내부 실행 순서는 화살표와 단계 번호로 읽음.**
- 위치를 실측 시간이나 처리 시간 비율로 해석하지 않음.

### 세로: Layer

| 예시 Layer | 소속 예시 |
|---|---|
| 데이터 / 파일 | 원본 CSV·문서·결과 파일 |
| 프론트엔드 | 파일 선택, 실행 클릭, 미리보기, 결과 화면 |
| 백엔드 | 요청 수신, 형식 검증, DB 조회, 분석 호출, 파일 응답 |
| 분석로직 | 규칙 판단, 중복 제거, 정렬, 계산 |
| DB | 입력·실행·결과의 저장소 |

- Layer는 처리 위치 또는 책임을 나타냄. 함수의 역할 색상과 별개.
- 분석로직이 백엔드가 호출하는 Python 함수라면 그 관계를 명시. 별도 서버라고 표현하지 않음.
- ‘저장·미리보기’처럼 여러 Layer를 묶은 단계는 노드를 나눔.
- 계층 수를 고정하지 않음. 필요하면 외부 API·작업 큐·사람의 승인 등을 추가하고, 없는 계층은 제외.

### 도형·색: 기능 역할

| 역할        | 기본 도형      | 배경 / 테두리              |
| --------- | ---------- | --------------------- |
| 입력·출력 데이터 | 평행사변형      | `#d6f1ed` / `#218779` |
| 사용자 조작·화면 | 사각형        | `#dbeaff` / `#426fa7` |
| 자동 처리     | 사각형        | `#ece1fa` / `#8660ad` |
| 조건 판단     | 마름모        | `#fff0c7` / `#ab8024` |
| 저장소       | 원통         | `#dcefdc` / `#4e8853` |
| 판정 결과     | 육각형        | `#e7ecf2` / `#657f98` |
| 오류 안내     | 구분되는 오류 노드 | `#f9d9d7` / `#b94a45` |

- Layer 배경은 옅은 중성색. 역할별 노드 색과 경쟁하지 않게 함.
- 선택은 금색 테두리·그림자로 표시하고 원래 역할 색을 유지.
- 범례를 그림 가까이에 배치. 색만으로 의미를 전달하지 말고 제목·도형도 사용.

## 4. 전체 구조와 상세 보기의 연결

- 전체 구조는 입력부터 결과까지 정상 경로, 주요 저장소와 재사용 연결을 포함.
- 상세 보기는 입력 / 분석 / 결과 등 업무 구간별로 제공. 조건·오류·반복이 많으면 상세에서 확장.
- **같은 단계는 모든 보기에서 동일한 노드 ID와 핵심 제목을 사용.**
- 예: 전체의 `②-1 심사 실행 요청`과 입력 상세 끝의 `②-1 심사 실행 요청`은 같은 `run` 노드.
- 상세의 마지막에 다음 구간 첫 노드를 다시 보여주면 ‘다음 구간: 실행·분석’처럼 경계를 표시.
- 제목에 모든 구현 내용을 넣지 말고, 왼쪽 상세에 입출력·목적·파일·함수를 풀어 씀.
- 입력 파일 종류가 다르면 독립 노드로 표시.
- 저장소는 저장 후 끝내지 않음. 이후 어떤 처리가 읽는지 연결.
- 사용자 재실행, 다음 항목 반복, 오류 재시도는 각각 구분. 조건과 누가 실행하는지 화살표에 표시.
- 예외·반복이 상세에만 있으면 전체 보기의 안내에 그 사실을 명시.

## 5. 기본 상태는 구조 보기

최초 진입과 초기화 후에는 구체적인 예시 건수·배정 인원을 표시하지 않음.

| 변수 | PKG B 예시 의미 |
|---|---|
| E | 직원 수 |
| N | 원본 신청 수 |
| U | 직원별 최신 신청 수 |
| D = N−U | 중복 제외 수 |
| C | 정원 |
| A / R / Q / W | 승인 / 반려 / 보완요청 / 대기 건수 |
| P | 승인된 참가 인원 |

- 파이프라인·양쪽 사이드바·입출력 크기·집계 모두 같은 상태를 사용.
- `Python 목록 N개`, `CSV N행 × 5열`, `정원 C명`처럼 표시.
- **근속 6개월, 동반 4명 이하, 파일당 2MB 같은 고정 규칙은 그대로 유지.** 예시 숫자와 규칙을 혼동하지 않음.
- 화면의 모든 숫자를 일괄 삭제하지 않음. 단계 번호·필드 수·규칙·API 상태 코드는 유지.
- 과거 수치가 포함된 참고 캡처와 개별 신청 기록은 기본 상태에서 숨기고 안내 문구 표시.

## 6. 내장 데이터 적용과 파라미터

1. 상단에서 데이터 출처 확인.
2. 실제 프로젝트에서 조절 가능한 파라미터 입력.
3. **적용** 버튼을 누르면 계산.
4. 파이프라인·사이드바·입출력 크기·집계·개별 신청을 같은 결과로 갱신.
5. 입력값만 바꾸면 아래는 기존 적용 결과를 유지하고 ‘변경사항 미적용’ 표시.
6. 잘못된 입력은 오류 안내. 직전 정상 결과는 보존.
7. **구조 보기로 초기화**하면 변수 표시로 복귀.

- PKG B의 데이터: 프로젝트 `data/employees.csv`, `data/applications.csv`를 수집한 내장 사본.
- 이 HTML은 파일을 실시간으로 읽지 않음. 출처 경로·수집 시점 표시. 원본 변경 시 내장 사본도 갱신.
- 조절 가능한 파라미터는 정원 정수 1~100000. 직원·신청 수는 데이터에서 계산하며 임의 입력 필드로 만들지 않음.
- 현재 예시의 적용 계산은 JavaScript로 원본 Python 규칙을 재현. 원본 서버 호출·DB 저장은 하지 않음.
- 원본 앱의 처리 구조와 시각화의 예시 계산을 구분해서 안내.
- 과거 앱 캡처를 적용 결과처럼 바꾸지 않음. ‘참고 캡처 · 이번 적용과 별개’라고 명시.
- 임의 CSV 업로드, 자동 재생, 속도, 다음 기록 버튼은 이 양식의 필수 기능이 아님. 현재 예시에는 없음.

## 7. 왼쪽 단계 설명의 순서

1. **Layer** — ‘레이어’ 대신 표제는 `Layer` 사용.
2. **단계 제목** — 중복 출력하지 않음.
3. **입력** — 항목마다 이름 / 실제 자료형 / 구조·크기 / 짧은 의미.
4. **출력** — 같은 기준으로 항목별 표시.
5. **단계 목적** — 왜 필요한 단계인지.
6. **세부 진행사항** — 순서, 조건, 실패 시 동작, 다음 단계.
7. **관련 파일 목록** — 파일 역할, 전체 경로, 관련 함수와 실제 줄 번호.
8. 필요할 때 참고 캡처·개별 판단·색상 구문 강조 코드·요구사항 근거.

### 자료형·크기 규칙

- `행 × 열` 순서. CSV·표의 헤더는 행 수에서 제외.
- 파일, Python 객체, JSON, DB, UI 테이블을 구분. 같은 정보라도 단계별 형식과 필드 수가 달라질 수 있음.
- `list[dict]`는 ‘목록 N개 / 각 M필드’로 표시하고 필요하면 ‘표 환산 N행 × M열’ 병기.
- JSON 객체는 필드 수와 주요 필드의 형식, JSON 배열은 항목 수·객체 구조 설명.
- 값 하나는 정수·실수·문자열·Boolean·날짜 표현 등을 명시. 문자열 날짜와 datetime 객체를 혼동하지 않음.
- 0/1 정수와 True/False Boolean을 구분.
- ‘승인/반려/보완/대기’는 네 가지 중 하나의 문자열이며 네 개의 Boolean이 아님.
- 조건 다이아몬드가 개념적 분기라면 별도 Boolean 반환 함수가 존재하는 것처럼 쓰지 않음.
- 현재 값은 내장 예시의 실제 계산에서 가져옴. 구조 상태에서는 N·M·C 등 변수 사용.
- DB 메타데이터 열, 결과 객체 필드, 화면에서 합친 열 때문에 생기는 차이를 설명.
- 확인되지 않은 값·행 수·함수·파일 위치는 추정하여 채우지 않음.

### 파일과 코드 근거

- 목록에는 짧은 파일 경로와 역할을 표시.
- 마우스오버/키보드 포커스 시 전체 절대 경로 표시.
- 특정 함수만 관련되면 함수명·실제 줄 번호까지 표시.
- 원본 코드를 읽어 연결. 그림을 먼저 만든 뒤 존재하지 않는 함수 이름을 붙이지 않음.
- 코드 구문 강조는 가독성 보조이며, 전체 코드나 원본 파일 위치로 추적 가능해야 함.

## 8. 구현 방식

### 각 도구가 맡는 범위

- Mermaid 11.17.2: 노드 도형·라벨·역할 색상·상세 flowchart 렌더링. 이 버전은 예시 제작 버전이며 최신 버전 추천을 뜻하지 않음.
- JavaScript/SVG: 전체 구조에서 Mermaid 노드를 업무 구간×Layer 좌표로 재배치하고 연결선을 다시 계산.
- HTML/CSS/JavaScript: 3열 화면, 너비 조절, 노드 상세, 입력 폼, 적용·초기화, 코드 강조.
- 참고 캡처는 기존 앱에서 수집한 이미지. 현재 적용 결과의 실시간 캡처가 아님.

### 새 환경에서 준비

Node.js와 npm을 사용할 수 있는 프로젝트 폴더에서 CMD 실행:

```bat
npm init -y
npm install mermaid@11.17.2
```

- 이미 package.json이 있으면 `npm init -y` 생략.
- 구현 시 Mermaid 코드를 렌더링하고, 배포용 HTML에는 필요한 라이브러리와 자료를 내장.
- CDN·절대경로 파일·별도 fetch에 의존하면 단일 오프라인 파일 요구를 만족하지 못함.
- 다른 프로젝트의 Python 계산이 필요하면 승인된 프로젝트 가상환경 사용. 전역 Python 실행을 전제로 하지 않음.

### 먼저 정의할 데이터

```javascript
// 구조 예시. 필드와 노드는 실제 프로젝트에 맞춰 채우기.
const node = {
  id: 'run',                         // 모든 보기에서 고정
  title: '②-1 심사 실행 요청',
  phase: 'analysis',
  layer: 'frontend',
  role: 'ui',
  purpose: '입력 데이터와 실행 조건으로 처리를 요청',
  inputs: [{ name: '정원', type: 'int', shape: 'scalar', symbol: 'C' }],
  outputs: [{ name: '요청 본문', type: 'JSON object', fields: ['batch_id', 'capacity'] }],
  files: [{ path: '실제 전체 파일 경로', function: '실제로 확인한 함수', line: null }]
};
```

- 노드 정의와 연결 관계를 먼저 정하고 전체/상세 보기에서 공유.
- 구간·Layer·역할은 별개 필드로 유지.
- 적용 데이터와 아직 적용하지 않은 입력값을 별도로 관리. 입력 이벤트가 적용 결과를 덮어쓰지 않게 함.
- 표현 함수는 현재 모드에 따라 `N` 또는 실제 건수를 표시. 계산에 문자열 변수를 섞지 않음.
- 신규 프로젝트로 옮길 때 현재 PKG B의 고정 좌표·컬럼·규칙·노드 ID를 그대로 사용하지 않음.

## 10. 완료 확인

- 첫 진입에서 E·N·U·C 등 변수 표시. 구체적 예시 건수·인원·개별 판정이 노출되지 않는가?
- 고정 규칙·단계 번호·필드 수는 정확히 유지되는가?
- 전체와 상세의 동일 노드가 같은 제목·설명·Layer를 가리키는가?
- 저장소가 이후 조회·다운로드·재실행과 연결되는가?
- 파라미터 수정만으로 결과가 바뀌지 않고, 적용 후 관련 영역이 함께 갱신되는가?
- 잘못된 값으로 적용하면 기존 결과가 유지되는가?
- 초기화 후 노드 클릭·상세 보기에서도 변수 상태가 유지되는가?
- 입력·출력의 자료형과 크기가 실제 코드와 일치하는가?
- 과거 캡처를 현재 결과로 오해할 여지가 없는가?
- 폭 조절·스크롤·확대·키보드 선택이 동작하고 글씨·화살표가 겹치지 않는가?
- 외부 인터넷 없이 한 파일로 열리는가?
- 예시 계산과 원본 구현을 비교했는가? 현재 PKG B는 정원 10·25·40명에서 원본 Python 기록의 신청별 판정·사유·인원 및 합계와 대조함.
- 도형 배치와 예시 계산은 구현했지만 원본 서버/DB를 실행하지 않는다면 명시했는가?
