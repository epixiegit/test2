# 지출 증빙 제출·승인 PRD

- 유형: 긴 PRD / 조직 내부용 신규 웹앱 / 첫 버전.
- 구성: 프론트엔드, 백엔드 API, DB, 로그인, 파일 업로드.
- 금액 단위와 승인 방식은 샘플용 가정이며 실제 조직 규정 확인 필요.

## 1. 문제
- 지출 내역과 영수증을 따로 전달해 증빙 누락과 중복 제출 확인이 어려움.
- 제출자가 현재 승인 상태를 별도로 문의해야 함.

## 2. 목표
- 지출 내역과 증빙을 묶어 제출.
- 제출·검토·승인 결과 기록.
- 첫 버전은 제출과 승인까지만 제공하며 실제 지급은 수행하지 않음.

## 3. 사용자·권한
- 직원: 본인 지출 작성·제출·조회.
- 승인자: 배정된 건 검토·승인·반려.
- 회계 담당자: 전체 승인 건 조회·내보내기.
- 관리자: 사용자와 승인자 설정.

## 4. 화면 구성
- 내 지출 목록.
- 지출 작성·상세.
- 승인 대기 목록.
- 회계 조회·다운로드.
- 사용자·승인자 설정.

## 5. 기능 요구사항
- 작성
  - 지출일, 사용처, 금액, 분류, 사용 목적 입력.
  - 영수증 이미지 또는 PDF 업로드.
  - 임시 저장 가능.
- 제출
  - 필수 항목과 증빙 존재 여부 확인.
  - 제출 완료 후 본문 수정 차단.
  - 승인자를 지정할 수 없으면 제출 차단 및 안내.
- 검토
  - 승인자가 내역과 첨부파일 확인.
  - 승인 또는 반려 처리.
  - 반려 사유 입력 필수.
- 재제출
  - 반려 건 수정 후 재제출.
  - 이전 제출 내용과 반려 이력 유지.
- 내보내기
  - 회계 담당자가 기간·분류로 승인 건 검색.
  - 검색 결과 CSV 다운로드.

## 6. 상태·규칙
- 상태: 작성 중·승인 대기·반려·승인 완료.
- 직원 본인은 본인 지출 승인 불가.
- 금액은 원 단위 양의 정수.
- 중복 클릭으로 제출 건이 여러 개 생성되지 않아야 함.
- 같은 날짜·사용처·금액이면 중복 가능성 경고.
- 같은 금액의 정상 지출도 가능하므로 경고만으로 제출 차단하지 않음.
- 승인 완료 건은 수정 불가.
- 승인 취소는 별도 운영 절차로 처리.

## 7. 데이터
- 사용자와 승인 관계.
- 지출 내역과 현재 상태.
- 증빙파일.
- 제출·승인·반려 이력.
- 처리자·처리 시각·반려 사유.

## 8. 보안·운영 조건
- 제출자와 배정 승인자는 해당 건 조회 가능.
- 회계 담당자는 승인 완료 건 조회 가능.
- 관리자는 계정 설정 권한만으로 지출 증빙 열람 권한을 얻지 않음.
- 파일 주소를 알아도 권한 없으면 다운로드 차단.
- 계정 비활성화 후에도 기존 승인 기록 유지.
- CSV는 UTF-8 BOM으로 제공.

## 9. 수용 기준
- 증빙 없이 제출하면 차단.
- 반려 시 제출자에게 사유 표시.
- 재제출 후에도 이전 반려 이력 확인 가능.
- 본인 승인 시도는 API에서 차단.
- 다운로드 금액 합계와 화면 조회 결과 합계 일치.

## 10. 제외·미정
- 제외: OCR, 자동 세무 판단, 은행 이체, 회계 시스템 연동.
- 미정: 승인 단계 수, 증빙 보관 기간, 승인자 부재 시 대체 절차.
