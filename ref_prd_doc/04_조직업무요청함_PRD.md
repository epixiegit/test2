# 조직 업무 요청함 PRD

- 유형: 보통 길이 PRD / 조직 내부용 신규 웹앱 / 첫 버전.
- 구성: 프론트엔드, 백엔드 API, DB, 로그인, 파일 업로드.
- 가상 프로젝트의 요구사항 예시.

## 1. 배경
- 시설·IT·총무 요청이 개인 메신저로 들어와 담당자와 처리 상태 확인이 어려움.

## 2. 목표
- 요청 접수부터 완료까지 한곳에서 추적.
- 요청자와 담당자가 같은 처리 상태 확인.

## 3. 사용자·권한
- 요청자: 요청 등록·본인 요청 조회·추가 설명 작성.
- 담당자: 배정된 요청 조회·상태 변경·답변 작성.
- 관리자: 전체 요청 조회·담당자 배정·분류 관리.

## 4. 사용자 흐름
- 로그인 → 요청 등록 → 관리자 배정 → 담당자 처리 → 완료 확인.

## 5. 기능 요구사항
- FR-01 요청 등록
  - 제목, 분류, 내용 입력.
  - 스크린샷·PDF 첨부 가능.
  - 필수 항목이 없으면 누락 항목 안내.
- FR-02 요청 조회
  - 상태·분류·등록일로 필터.
  - 상세 화면에서 첨부파일과 처리 이력 확인.
- FR-03 처리
  - 상태: 접수·처리 중·완료·취소.
  - 담당자와 관리자가 접수 → 처리 중 → 완료로 변경.
  - 완료 시 처리 내용 입력 필수.
- FR-04 추가 설명
  - 요청자와 담당자가 댓글 작성.
  - 댓글 작성자와 시간 기록.

## 6. 데이터·규칙
- 요청, 첨부파일, 댓글, 담당자, 상태 변경 이력 저장.
- 요청자는 접수 상태에서만 취소 가능.
- 완료된 요청의 본문 수정 불가.
- 첨부파일은 해당 요청의 조회 권한이 있는 사람만 다운로드.

## 7. 완료 기준
- 새 요청이 접수 상태로 저장.
- 담당자 변경과 상태 변경 이력 확인 가능.
- 권한 없는 사용자의 상세 API·첨부파일 접근 차단.

## 8. 제외·미정
- 제외: 메신저 연동, 자동 담당자 추천.
- 미정: 완료된 요청의 재접수 허용 여부.
