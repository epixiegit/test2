# 문서 검토·승인함 PRD

- 유형: 긴 PRD / 조직 내부용 신규 웹앱 / 첫 버전.
- 구성: 프론트엔드, 백엔드 API, DB, 로그인, 파일 업로드.
- 검토 방식과 역할은 샘플용 가정.

## 1. 배경·목표
- 이메일·메신저에 분산된 검토로 최종본과 승인 여부 혼동.
- 검토할 파일 버전과 승인 결과를 연결해 관리.

## 2. 사용자
- 작성자: 문서 등록·검토 요청·수정본 제출.
- 검토자: 문서 열람·의견 작성·승인·반려.
- 관리자: 사용자 관리·전체 진행 현황 조회.

## 3. 제공 화면
- 로그인.
- 내가 작성한 문서.
- 내가 검토할 문서.
- 문서 상세와 버전 목록.
- 관리자 현황.

## 4. 핵심 기능
- 제목·설명·검토자를 입력하고 문서 업로드.
- 초안 저장 후 검토 요청.
- 검토자가 의견을 남기고 승인 또는 반려.
- 작성자가 수정본을 새 버전으로 제출.
- 문서별 최신 상태와 과거 버전 확인.

## 5. 검토 방식
- 첫 버전은 검토자 한 명만 지정.
- 검토 상태: 초안·검토 중·반려·승인·철회.
- 검토 요청 이후 해당 버전의 파일 교체 불가.
- 반려 또는 철회 후 수정본 제출 시 버전 증가.
- 승인은 특정 버전에 연결.
- 새 버전은 이전 버전의 승인을 자동 승계하지 않음.

## 6. 파일 처리
- PDF·DOCX·XLSX 업로드 허용.
- 다운로드 검토를 기본으로 제공.
- 브라우저 내 편집과 문서 본문 주석 제외.
- 업로드 실패 시 제목·설명 입력값 유지.
- 같은 이름의 파일도 서로 다른 버전으로 식별.

## 7. 권한
- 작성자와 지정 검토자는 문서·파일 접근 가능.
- 관리자는 전체 진행 현황만 조회하며 파일 열람 권한은 별도 부여하지 않음.
- 작성자는 검토 중인 요청 철회 가능.
- 철회 이후 승인 시도 시 현재 상태 안내 및 차단.
- 승인된 버전은 삭제·수정 불가.
- 관리자의 별도 보관 종료 기능은 첫 버전에서 제외.

## 8. 기록
- 문서 기본정보와 버전별 파일.
- 검토 요청·철회·승인·반려 이력.
- 의견·처리자·시각.
- 계정 비활성화 이후에도 작성·검토 이력 유지.

## 9. 완료 기준
- v1 승인 후 v2를 올리면 v2는 미승인 상태.
- 반려 사유와 해당 버전을 함께 확인 가능.
- 철회와 승인이 동시에 요청되어도 최종 상태가 모순되지 않음.
- 권한 없는 사용자의 파일 직접 다운로드 차단.

## 10. 위험·미정
- 위험: 다운로드한 구버전을 최종본으로 오인.
- 대응: 다운로드 전 버전·승인 상태 표시.
- 미정: 승인 후 새 버전을 만들 수 있는 역할과 보관 기간.
