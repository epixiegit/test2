# 웹서버 검증 예시 — API와 화면을 각각 확인하기

[처음으로](README.md) · [분석 검증](02_분석검증_예시.md) · [검증 기록 양식](05_검증기록_템플릿.md)

## 1. 여기서 무엇을 확인하나

- **API 테스트:** 화면 뒤에서 데이터를 주고받는 요청에 올바른 응답이 오는지 확인.
- **화면 테스트:** 사람이 실제로 선택·클릭했을 때 숫자·표·오류 안내가 맞게 바뀌는지 확인.
- **전체 연결 확인:** 입력 데이터 → 계산 → API → 화면 → 내려받은 파일이 같은 결과를 나타내는지 확인.
- 이 폴더의 실습 서버는 **Python 기본 기능과 HTML**로 만든 작은 예제. FastAPI·React 설치 없이 검증 흐름을 익히기 위한 구성.
- 아래 금액·상태코드는 **이 실습에서 정한 기준**. 실제 과제에는 해당 프로젝트의 요구사항·응답 형식·테스트 데이터를 적용.

## 2. API를 확인하는 순서

서버 시작 방법과 승인된 Python 실행 환경은 [README](README.md) 참고. 로컬 실습의 기본 주소는 `http://127.0.0.1:8000`. 웹 IDE에서는 플랫폼이 제공한 미리보기 주소와 실제 포트를 사용.

| 요청 | 확인할 내용 | 기대 결과 |
| --- | --- | --- |
| `GET /health` | 서버 응답 여부 | HTTP 200, `{"status":"ok"}` |
| `GET /api/summary` | 취소 건 제외 후 합계 | `record_count=5`, `total_amount=35000` |
| `GET /api/summary?department=품질` | 선택한 부서만 집계 | `record_count=1`, `total_amount=5000` |
| `GET /api/summary?department=없는부서` | 결과가 없는 조건 | 0건, 0원, `by_department=[]` |
| `GET /api/export.csv?department=품질` | 내려받은 파일과 화면 일치 | 품질 1건·5,000원 한 행, UTF-8 BOM |
| `POST /api/preview`에 정상 JSON 전달 | 보내준 행의 계산 | 승인 행만 집계 |
| 같은 요청에 중복 ID·음수 금액 전달 | 잘못된 데이터 거절 | HTTP 422 |
| 같은 요청에 문법이 깨진 JSON 전달 | 해석할 수 없는 요청 거절 | HTTP 400 |
| 존재하지 않는 주소 요청 | 잘못된 경로 처리 | HTTP 404 |

- **HTTP 200은 요청이 성공했다는 신호이지, 계산이 맞다는 증거가 아님.** 응답 본문의 숫자도 확인.
- 전체 결과의 `by_department`에는 생산 2건·20,000원, 품질 1건·5,000원, 영업 2건·10,000원이 있어야 함.
- 부서별 금액 합계 35,000원, 건수 합계 5건을 전체 값과 대조. 정렬 순서 자체를 요구하지 않았다면 행 순서 때문에 실패로 판단하지 않기.

정상 미리보기 요청의 작은 예:

```json
{"rows":[
  {"request_id":"T001","department":"품질","amount":5000,"status":"approved"},
  {"request_id":"T002","department":"품질","amount":9000,"status":"cancelled"}
]}
```

기대값은 승인 1건·5,000원. 이 입력의 기대값을 손으로 먼저 정하고 실제 응답과 비교.

## 3. 브라우저에서 직접 해볼 7가지

| 순서 | 사람이 하는 행동 | 통과 기준 |
| --- | --- | --- |
| 1 | 예제 첫 화면 열기 | 전체 승인 5건·35,000원, 부서별 3행 |
| 2 | 부서를 ‘품질’로 선택 | 1건·5,000원, 품질 한 행 |
| 3 | 품질 조건으로 CSV 내려받기 | 파일을 열면 품질 1건·5,000원. 전체 부서가 섞이지 않음 |
| 4 | ‘없는부서(빈 결과 실습)’ 선택 | 빈 결과 안내, 0건·0원. 이전 품질 결과가 남지 않음 |
| 5 | 다시 ‘전체’ 선택 | 승인 5건·35,000원으로 복원 |
| 6 | 새로고침 | 화면과 현재 선택 조건이 일치. 이 예제는 초기 전체 조건으로 돌아와도 됨 |
| 7 | 연습 서버를 중지한 뒤 다시 조회 | 오류 안내가 보이고 이전 숫자·표를 정상 결과처럼 보여주지 않음 |

- 7번은 **연습 예제 서버에서만** 수행. 서버 터미널에서 `Ctrl+C` → 열린 화면에서 재조회 → 오류 확인 → 서버 재시작 → 재조회로 복구 확인.
- 서버를 중지하지 않고 브라우저의 네트워크 차단으로 재현했다면, 기록에도 ‘네트워크 차단’이라고 적기.
- 화면을 열어보지 않았다면 ‘화면 검증 통과’로 적지 않기.
- 다운로드 성공 알림만 확인하지 말고 **실제 파일을 다시 열어 내용**을 비교.
- 서버 상태 확인만 했다면 1~7번을 모두 수행한 것으로 기록하지 않기.

## 4. 이상하면 어디를 보나

브라우저에서 `F12`를 누르고 **Network(네트워크)**와 **Console(콘솔)** 확인. 시험 미리보기에서 개발자 도구를 쓸 수 없다면 AI에게 API 요청·서버 로그 확인을 맡기고, 화면 관찰과 구분해 기록.

| 관찰한 현상 | 다음에 확인할 것 |
| --- | --- |
| 화면은 열리지만 숫자가 안 나옴 | Network에서 집계 API가 호출됐는지, 실제 요청 주소·포트가 맞는지 |
| API 응답이 404 | 브라우저가 호출한 경로와 백엔드에 구현한 경로가 같은지 |
| API 응답은 200인데 합계가 틀림 | 응답 본문 숫자 → 분석 함수 → 원본 데이터 순으로 확인 |
| API 숫자는 맞는데 화면이 틀림 | 화면의 필드명 연결, 단위·반올림, 이전 요청 결과가 남았는지 |
| 품질 선택인데 생산 결과가 보임 | 요청에 부서 조건이 들어가는지, 화면이 최신 응답을 쓰는지 |
| CSV만 전체 데이터가 나옴 | 다운로드 요청에도 현재 필터를 전달하는지 |
| 오류 뒤에도 이전 합계가 보임 | 오류 처리 시 오래된 값을 지우거나 ‘이전 결과’라고 명확히 표시하는지 |

처음부터 여러 곳을 동시에 고치지 말고, **틀린 결과가 처음 나타나는 구간**을 좁혀 수정한 뒤 같은 입력으로 다시 확인.

## 5. 실제 FastAPI 프로젝트에 적용하기

FastAPI의 `TestClient`로 요청을 보내 상태코드와 JSON 내용을 검사할 수 있음. 아래는 수정해서 가져갈 **예시**이며, 이 폴더의 기본 데모를 실행하는 코드는 아님. [FastAPI 공식 테스트 안내](https://fastapi.tiangolo.com/tutorial/testing/)

```python
from fastapi.testclient import TestClient
from app.main import app  # 실제 프로젝트의 FastAPI app 위치로 변경

def test_quality_summary():
    # 실제 프로젝트에서도 테스트용 데이터가 품질 승인 5,000원 1건이어야 함.
    with TestClient(app) as client:
        response = client.get("/api/summary", params={"department": "품질"})
    assert response.status_code == 200
    data = response.json()
    assert data["record_count"] == 1
    assert data["total_amount"] == 5000
```

- 프로젝트의 가상환경에 필요한 `pytest`, `httpx`, `fastapi`가 있는지 먼저 확인.
- Windows CMD 예: `".venv\Scripts\python.exe" -m pytest tests -q`. 실제 가상환경·테스트 폴더에 맞춰 변경.
- **TestClient 통과만으로 실제 포트·미리보기 연결·화면까지 확인된 것은 아님.** API 테스트 후 서버를 실제로 실행하고 브라우저에서도 확인.
- 실데이터가 매번 달라지는 상태에서 무조건 5,000원을 기대하지 않기. 입력을 고정하거나, 해당 입력의 독립적인 정답을 먼저 만들기.

## 6. 실제 React 화면에 적용하기

- 프로젝트의 `package.json`에 `build` 스크립트가 있다면 `npm run build`로 빌드 오류 확인. Vite 프로젝트의 빌드·미리보기 방법은 [Vite 공식 안내](https://vite.dev/guide/static-deploy.html) 참고.
- **빌드 성공만으로 버튼·필터·API 연결이 맞다고 판정하지 않기.** 실제 브라우저에서 위 7가지와 프로젝트 핵심 사용자 흐름 확인.
- 반복할 화면 검증은 Playwright로 자동화 가능. 클릭 이후 결과 문구나 숫자가 기대값이 될 때까지 확인하는 assertion을 사용. [Playwright 공식 assertion 안내](https://playwright.dev/docs/test-assertions)
- 프론트와 백엔드의 프로토콜·주소·포트가 다르면 CORS 설정이 관련될 수 있음. 허용할 실제 프론트 주소와 요청을 확인. 이 예제는 같은 서버에서 화면과 API를 제공하므로 다른 출처 간 연결을 검증하지 않음. [FastAPI 공식 CORS 안내](https://fastapi.tiangolo.com/tutorial/cors/)

## 7. 이 예제를 통과해도 아직 확인되지 않은 것

- 실제 프로젝트의 React 코드·FastAPI 코드와 데이터.
- 웹 IDE의 포트 공개·미리보기·프록시 경로.
- 로그인·사용자별 권한, DB 저장·재시작 후 유지, 동시 수정, 대용량 성능.
- **해당 기능이 실제 과제에 있을 때** 그 기능에 맞는 테스트를 추가. 없는 기능을 검증하려고 구현 범위를 늘릴 필요는 없음.
