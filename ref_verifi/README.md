# 분석 + 웹서버 검증 실습

**처음에는 이 문서만 읽고, 아래 1~4단계를 순서대로 해보면 됩니다.**

- 검증: 내가 만들려던 결과가 실제로 맞는지 확인하는 일.
- 테스트: 입력과 기대 결과를 정해 실제 결과와 비교하는 구체적인 방법.
- 예: 버튼이 눌리는지만 보는 것이 아니라, **승인 구매 5건이 35,000원으로 집계되는지**까지 확인.
- 이 자료는 학습·재사용을 위한 예제입니다. 대회의 공식 채점표나 모든 프로젝트에 충분한 검사 목록은 아닙니다.

## 예제의 업무 조건과 정답

회사 구매 요청을 부서별로 집계합니다. **approved(승인)만 포함하고 cancelled(취소)는 제외**합니다.

| 요청 | 부서 | 금액(원) | 상태 |
|---|---|---:|---|
| R001 | 생산 | 12,000 | approved |
| R002 | 생산 | 8,000 | approved |
| R003 | 품질 | 5,000 | approved |
| R004 | 품질 | 9,000 | cancelled |
| R005 | 영업 | 7,000 | approved |
| R006 | 영업 | 3,000 | approved |

- 손계산: 생산 20,000 + 품질 5,000 + 영업 10,000 = **총 35,000원 / 승인 5건**.
- 전체 입력 6건과 승인 5건은 서로 다른 지표입니다.
- 취소까지 더한 **44,000원은 이 요구사항에서는 오답**입니다.
- 정답 파일 [expected_summary.json](demo/data/expected_summary.json)은 이 손계산에서 작성했습니다. 프로그램 결과를 복사해 정답으로 만든 것이 아닙니다.
- 입력 정책: 필수 항목 누락·ID 중복·음수·비정수 금액·알 수 없는 상태는 오류. 0원은 허용. 빈 결과는 0건·0원.
- 이 정책은 실습용으로 정한 것입니다. 실제 과제의 중복·취소·결측 처리 기준은 현업과 먼저 확인하세요.

## 1. 실행할 Python 확인

- **Python 3.10 이상**, 외부 패키지 설치는 필요 없습니다.
- 프로젝트 가상환경의 Python 또는 사용자가 승인한 실행 환경을 사용합니다.
- 아래 예시의 `C:\project\.venv\Scripts\python.exe`는 본인 경로로 바꿉니다.
- 이 폴더에 `.venv`가 있다면 BAT가 해당 환경만 사용합니다. 없다고 시스템 전역 Python으로 자동 전환하지 않습니다.
- 환경이 없다면 Codex에게 다음처럼 요청하세요:

```text
이 검증 예제를 실행하려고 한다. 사용할 수 있는 프로젝트 가상환경을 먼저 확인해줘.
없다면 사용할 기반 Python과 가상환경 경로를 제안하고 확인받아줘.
이 실습에는 외부 패키지가 필요 없으니 불필요한 설치는 하지 마.
```

## 2. 정상 코드 테스트 실행

터미널의 작업 위치를 이 `ref_verifi` 폴더로 이동한 뒤 실행합니다.

Windows CMD:

```bat
run_tests.bat "C:\project\.venv\Scripts\python.exe"
```

직접 실행하거나 일부만 검사하려면:

```bat
"C:\project\.venv\Scripts\python.exe" demo\run_tests.py --group analysis --report
"C:\project\.venv\Scripts\python.exe" demo\run_tests.py --group api --report
```

Linux 웹 IDE에서 기존 프로젝트 가상환경을 사용하는 예:

```sh
/path/to/project/.venv/bin/python demo/run_tests.py --report
```

- 정상 예제에서는 `OK`와 종료코드 `0`이 기대 결과입니다.
- 검사가 0개이거나 건너뛴 검사가 있으면 `INCOMPLETE`와 종료코드 `2`로 표시합니다. 실행하지 못한 검사를 통과로 세지 않습니다.
- API 검사는 빈 포트에 실습 서버를 잠깐 실행하고 종료합니다. 다른 서버를 미리 켤 필요 없습니다.
- `--report`를 붙이면 `.runs/실행시각/summary.json`, `test_log.txt`에 증거를 남깁니다. 새 실행은 새 폴더이므로 이전 기록을 덮어쓰지 않습니다.
- **이 결과만으로 브라우저 버튼·JavaScript·React가 정상이라고 판단하지 않습니다.** 자동 기록에도 `browser_tested: false`라고 표시합니다.

## 3. 일부러 실패하는 테스트 읽어보기

```bat
"C:\project\.venv\Scripts\python.exe" demo\run_tests.py --bug-demo --report
```

예상되는 핵심 출력:

```text
FAIL: test_cancelled_request_must_be_excluded
AssertionError: 44000 != 35000
```

- **실패를 재현하는 학습 명령**이므로 종료코드 1이 의도된 결과입니다.
- 기대값 35,000원과 실제값 44,000원의 차이 9,000원이 취소 요청과 일치합니다.
- [bug_demo.py](demo/bug_demo.py)는 상태 필터를 빠뜨린 코드입니다.
- [analysis.py](demo/analysis.py)의 `summarize`는 승인만 포함하는 정상 구현입니다. 정상 구현의 테스트를 다시 실행하면 같은 업무 조건을 만족하는지 확인할 수 있습니다.
- 실패를 없애려고 정답을 44,000원으로 바꾸면 버그를 숨기는 것입니다. 요구사항이 바뀐 경우에만 근거와 함께 기대값을 수정하세요.

## 4. 브라우저에서 확인

Windows CMD, 첫 번째 터미널:

```bat
run_server.bat "C:\project\.venv\Scripts\python.exe"
```

브라우저 주소: `http://127.0.0.1:8000/`. 종료: 서버 터미널에서 `Ctrl+C`.

Linux 웹 IDE:

```sh
/path/to/project/.venv/bin/python demo/server.py --host 0.0.0.0 --port 8000 --verbose
```

- 웹 IDE에서는 플랫폼의 **8000번 포트 미리보기**로 접속합니다. `0.0.0.0`은 서버가 연결을 받을 바인딩 주소입니다. 브라우저 접속 주소는 플랫폼에서 제공하는 주소를 사용하세요.
- 포트가 이미 사용 중이면 기존 서버를 함부로 종료하지 마세요. Windows에서는 아래처럼 Python을 직접 실행하면 8001번으로 바꿀 수 있습니다. BAT에 인수를 추가하는 방식은 지원하지 않습니다.

```bat
"C:\project\.venv\Scripts\python.exe" demo\server.py --host 127.0.0.1 --port 8001 --verbose
```

- 이 경우 브라우저 주소도 `http://127.0.0.1:8001/`로 바꿉니다.
- 전체 → 품질 → 없는부서 → CSV 다운로드 → 새로고침을 확인합니다.
- 서버를 중지한 상태에서 다시 조회하면 오류가 보이고 이전 숫자·표가 사라져야 합니다.
- 자세한 기대값과 실패 해석은 [웹서버 검증](03_웹서버검증_예시.md)을 참고합니다.

## 실제 내 프로젝트에 옮겨 쓰기

1. 과제 요구사항에서 중요한 행동과 숫자 3~5개를 선정합니다.
2. 사람이 확인한 작은 입력과 기대값을 먼저 만듭니다.
3. 예제 테스트의 입력·기대값·함수·API 경로를 **내 프로젝트 계약에 맞게** 바꿉니다.
4. 처음 실패한 원인을 고친 뒤 같은 테스트를 다시 실행합니다.
5. 실제 화면과 실행 환경에서 마지막으로 확인하고, 실행한 증거와 미검증 범위를 남깁니다.

이 예제의 테스트가 통과했다는 이유로 내 프로젝트도 통과했다고 기록하면 안 됩니다. 예제는 표준 라이브러리 서버이며 **FastAPI·React·DB·로그인 구현을 포함하지 않습니다.** 해당 기능이 있는 실제 프로젝트에서는 추가 검증이 필요합니다.
