# 검증을 AI에게 요청하는 프롬프트

[시작 안내](README.md) · [체크리스트](01_검증순서_체크리스트.md) · [분석 예시](02_분석검증_예시.md)

- 대괄호 항목을 실제 프로젝트 내용으로 바꿔서 사용한다.
- 모든 요청은 현재 세션의 역할·파일 권한과 이미 정한 공통규칙을 따른다.
- 테스트 코드 작성·실행은 허용된 경로와 승인된 실행 환경에서 수행한다. 검토 전용 세션에는 제안·보고만 맡긴다.
- 프롬프트를 보냈다는 사실이나 AI의 “문제없음”이라는 말만으로 검증 완료 처리하지 않는다.

## 1. 무엇을 검사할지 정하기 — 동료 또는 메인

```text
이 프로젝트의 검증 계획을 만들어줘.

입력 자료: [과제 README, 현업 확인 내용, 원본 데이터 경로]
핵심 사용자 흐름: [예: 부서 선택 → 승인 금액 확인 → CSV 다운로드]
검토 범위: [이번에 제출할 기능]

먼저 목표·필수 조건·제외 범위·미확인 조건을 구분해.
그다음 목표 달성에 영향이 큰 검증부터 제시해.
각 검증에 입력, 기대 결과, 기대 결과의 근거, 실행 방법을 붙여줘.
정상 입력뿐 아니라 빈 결과·잘못된 입력·핵심 경계 조건도 포함해.
기대값은 요구사항이나 작은 샘플의 독립 계산에서 정하고,
현재 구현이 출력한 값을 그대로 정답으로 채택하지 마.
불명확한 업무 규칙은 임의 확정하지 말고 확인 질문으로 남겨.
아직 코드·원본 데이터는 수정하지 말고, 필요한 검증 계획부터 보여줘.
```

**예상 진행:** AI가 “취소 포함 여부가 미확정”이라고 표시 → 사람이 현업에 확인 → 승인만 포함으로 확정 → 작은 샘플의 기대값을 정함. 시험의 실제 답변을 AI가 대신 지어내게 하지 않는다.

## 2. 분석·API 테스트를 만들고 실행하기 — 메인

```text
확정한 검증 계획에 따라 핵심 테스트를 만들고 실행해줘.

프로젝트: [실제 경로]
확정한 기준: [예: 승인 요청만 포함, 금액은 0 이상 정수 원]
독립 기대값: [입력 샘플과 손계산 결과]
사용 가능한 실행 환경: [승인된 프로젝트 가상환경의 Python 경로]
쓰기 허용 범위: [허용된 테스트·결과 폴더]

기존 테스트가 있으면 먼저 확인하고 재사용해.
원본 데이터는 수정하지 말고 작은 테스트 입력을 따로 사용해.
각 테스트가 어떤 요구사항을 확인하는지 알 수 있게 작성해.
코드의 계산 절차를 그대로 복제해서 기대값을 만들지 마.
환경이 없거나 권한 밖의 변경이 필요하면 그 부분은 실행하지 말고 알려줘.
실제 실행 명령·입력·기대값·실제값·판정·결과 경로를 보고해.
실행하지 않은 항목과 코드만 검토한 항목을 통과로 표시하지 마.
테스트 때문에 시작한 서버나 프로세스는 끝나면 정리해.
```

**예상 진행:** 테스트 작성 → 승인된 환경에서 실행 → 실패 시 기대/실제 차이 제시. API 응답 검사가 통과해도 브라우저 검사까지 끝났다고 보고하면 안 된다.

## 3. 실제 웹 화면 검증하기 — 메인 또는 실행 권한이 있는 검증 세션

```text
내 프로젝트를 실제 브라우저에서 확인해줘.

접속 주소: [실제 미리보기 URL 또는 localhost 주소]
시나리오: [예: 품질 선택 → 조회 → 1건·5,000원 확인 → CSV 다운로드]
기대값 근거: [확정한 업무 기준과 독립 계산]
결과·다운로드 저장 위치: [프로젝트 안의 허용된 폴더]

사용 가능한 브라우저 도구로 실제 입력·클릭·화면 변화를 확인해.
정상 흐름, 빈 결과, 오류 표시를 필요한 범위에서 구분해 확인해.
필터를 바꾼 뒤 이전 결과가 남지 않는지 확인해.
다운로드 파일을 다시 읽고 화면 조건·건수·금액과 비교해.
서버 응답, 브라우저 동작, 사람이 확인한 화면을 구분해 보고해.
화면을 열 수 없으면 API 검사만으로 화면 통과를 선언하지 마.
다운로드와 증거는 지정한 폴더 안에만 저장하고,
이 작업에서 새로 띄운 브라우저·서버만 사용 후 정리해.
```

**예상 진행:** “품질 1건·5,000원” 화면 확인 + 내려받은 CSV 확인. 브라우저 도구가 없다면 미실행 사유와 사람이 직접 할 절차를 받는다.

## 4. 실패를 수정하고 다시 확인하기 — 메인

```text
다음 검증 실패를 분석하고 수정해줘.

재현 입력·명령: [실제 사용한 입력과 명령]
기대 결과와 근거: [요구사항·손계산·공식 동작]
실제 결과·오류: [로그 또는 결과]

먼저 원인이 요구사항·입력·구현·테스트·환경 중 어디에 있는지 구분해.
기대값이 맞다는 근거를 확인한 뒤 원인에 해당하는 부분을 수정해.
통과시키려고 기대값을 임의 변경하거나 실패 검사를 삭제하지 마.
업무 기준 자체를 바꿔야 한다면 이유와 영향을 먼저 알려줘.
수정 후 실패했던 테스트와 영향을 받는 기존 테스트를 다시 실행해.
변경 내용·재검증 결과·아직 확인하지 못한 사항을 보고해.
현재 세션의 수정·삭제 승인 규칙과 허용 경로를 지켜줘.
```

**예시:** 기대 35,000원인데 실제 44,000원 → 취소 9,000원 포함 여부 확인 → 승인 필터 수정 → 전체·품질 필터·다운로드를 다시 확인.

## 5. 제출 전 근거 점검과 설명 연습 — 메인 또는 레드팀

```text
제출 전에 검증 근거와 내가 설명할 내용을 점검해줘.

참고할 자료: [확정 요구사항, 최종 코드, 테스트 결과, 실제 화면 확인 기록]

핵심 요구사항마다 대응하는 구현과 검증 근거를 연결해줘.
각 항목은 통과·실패·미실행·검토만 중 실제 상태로 구분해.
이전 코드 버전의 결과를 최신 구현의 근거로 사용하지 마.
빠진 근거가 있으면 목표에 미치는 영향과 확인 방법을 제시해.
검토 권한만 있다면 직접 실행·수정하지 말고 필요한 작업을 보고해.

마지막으로 내가 내 결과물을 3분 안에 설명할 수 있도록 질문 5개를 내줘.
문제와 성공 기준, 주요 판단 이유, 데이터 흐름, 검증 근거,
한계·장애 발생 시 대응을 내 구현에 맞춰 질문해.
답변은 내가 먼저 하게 하고, 근거가 부족한 부분을 짚어줘.
```

이 설명 연습은 시험 전 준비용이다. 실제 평가에서 AI 사용이 제한되는 구간은 해당 규정을 따른다.
