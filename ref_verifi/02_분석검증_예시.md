# 분석 검증 예시 — 부서별 승인 구매금액

[시작 안내](README.md) · [체크리스트](01_검증순서_체크리스트.md) · [AI 요청문](04_AI에게시키는프롬프트.md)

## 먼저 사람이 정할 업무 규칙

이번 실습은 “부서별로 승인된 구매 요청의 건수와 금액을 보고 싶다”는 상황이다.

- 한 행은 구매 요청 한 건이다.
- `status=approved`인 행만 집계한다.
- `status=cancelled`인 행은 집계에서 제외한다.
- 금액 단위는 원이며, 0 이상의 정수다. 0원 요청도 승인 건수에는 포함한다.
- 요청 ID는 중복되면 안 된다.
- 필수 값 누락·잘못된 금액·알 수 없는 상태는 오류로 알린다. 임의 삭제나 보정으로 숨기지 않는다.
- 조건에 맞는 승인 요청이 없으면 0건·0원이다.

**이 규칙은 예제를 위한 약속이다.** 실제 회사에서 취소·반품·음수 금액을 다루는 방식은 업무 담당자에게 따로 확인해야 한다.

## 1. 원본 6건을 직접 읽기

원본 파일: [demo/data/requests.csv](demo/data/requests.csv)

- `R001 / 생산 / 12000 / approved`
- `R002 / 생산 / 8000 / approved`
- `R003 / 품질 / 5000 / approved`
- `R004 / 품질 / 9000 / cancelled`
- `R005 / 영업 / 7000 / approved`
- `R006 / 영업 / 3000 / approved`

열 이름은 `request_id`, `department`, `amount`, `status`다. 파일의 실제 줄 수가 아니라 CSV를 읽은 데이터 행 수가 6건인지 확인한다.

## 2. 코드를 실행하기 전에 정답 만들기

- 생산: R001 + R002 → `12000 + 8000 = 20000원`, **2건**.
- 품질: R003만 포함 → **5000원, 1건**. R004는 취소이므로 제외.
- 영업: R005 + R006 → `7000 + 3000 = 10000원`, **2건**.
- 전체: `20000 + 5000 + 10000 = 35000원`, **5건**.

이 기대값은 원본 6건과 업무 규칙을 직접 대조해 구한 값이다. 분석 함수의 실행 결과를 복사해서 정답 파일에 넣는 방식으로 만들지 않는다.

## 3. 정상 입력을 넣어 실제 결과와 비교

승인된 Python 환경에서 `demo/run_tests.py --group analysis`를 실행한다. 정확한 Windows·웹 IDE 실행 방법은 [README](README.md)를 따른다.

확인할 질문:

- 전체 합계가 **35,000원**인가?
- 승인 건수가 **5건**인가?
- 생산·품질·영업의 결과가 위의 손계산과 각각 일치하는가?
- 부서별 합계의 합이 전체 합계와 일치하는가?
- 품질로 필터링하면 **1건·5,000원**인가?

“부서별 합계의 합 = 전체 합계”만 맞는 것은 충분하지 않다. 두 값에 취소 건을 함께 잘못 포함해도 서로 일치할 수 있기 때문이다. **독립적인 손계산 정답**을 함께 확인해야 한다.

## 4. 일부러 잘못 계산한 경우

취소 요청을 제외하지 않고 전부 더하면:

```text
12000 + 8000 + 5000 + 9000 + 7000 + 3000 = 44000
```

- 기대값: **35,000원**.
- 실제값: **44,000원**.
- 차이: **9,000원**.
- 확인할 원인: 품질 부서의 취소 요청 R004가 포함됐는지.
- 고칠 대상: 승인 조건을 누락한 계산 코드.
- 고치면 안 되는 행동: 테스트의 기대값을 44,000원으로 바꿔서 통과시키기.
- 재확인: 전체 합계뿐 아니라 품질 필터·다운로드 값에도 수정이 반영됐는지.

`demo/run_tests.py --bug-demo`는 이런 실패를 보여주는 실습이다. 일부러 틀린 예제를 검사하므로 실패와 종료 코드 1이 나오는 것이 의도된 동작이다. 기본 정상 테스트와 구분한다.

## 5. 정상 데이터 외에 무엇을 넣어볼까

- **빈 입력:** 요청 0건 → 결과 0건·0원.
- **모두 취소:** 승인 요청 0건 → 결과 0건·0원.
- **없는 부서 필터:** 조건에 맞는 행 0건 → 결과 0건·0원.
- **0원 승인 요청:** 금액은 늘지 않지만 승인 건수는 1건 증가.
- **같은 ID 두 번:** 중복이라고 오류를 알려야 함. 두 건으로 합산하지 않음.
- **금액 `-1`:** 이번 예제 규칙에 위배되므로 오류.
- **금액 `12.5` 또는 `abc`:** 정수 원 단위가 아니므로 오류.
- **빈 부서 또는 필수 열 누락:** 오류로 알림.
- **상태 `pending`:** 이번 예제가 정의하지 않은 상태이므로 오류.

이 목록은 필요한 검증 사례다. 현재 실행한 자동 테스트에 무엇이 포함됐는지는 실제 테스트 결과에서 확인한다. 목록에 적혀 있다는 이유만으로 실행 완료 처리하지 않는다.

## 6. 내 분석 프로젝트에 적용하는 방법

### groupby를 쓰는 경우

- 묶는 기준이 부서명인지 부서 코드인지 정한다.
- `생산`, `생산 `처럼 표기가 다른 값을 같은 부서로 볼지 결정한다.
- 합계에 포함되는 상태·기간·대상을 먼저 확인한다.
- 건수를 셀 때 행 수인지, 중복 제거한 요청 수인지 구분한다.
- 필터 조건을 적용한 작은 샘플을 직접 계산하고 비교한다.

### 두 테이블을 합치는 경우

예: 구매 요청에 부서 마스터를 붙였는데 마스터에 같은 부서 코드가 두 번 있으면, 요청 행이 늘어나 금액도 두 번 더해질 수 있다.

- 합치기 전후 행 수와 요청 ID 개수를 비교한다.
- 마스터의 연결 키가 유일해야 하는지 확인한다.
- 매칭되지 않은 행이 사라지거나 미분류로 남는지 확인한다.
- pandas에서는 관계에 맞춰 `merge(..., validate="many_to_one", indicator=True)`를 사용할 수 있다. `many_to_one`은 오른쪽 연결 키의 유일성을 검사하고, `indicator`는 매칭 여부를 표시한다. 실제 데이터 관계에 맞게 선택해야 한다. [공식 설명](https://pandas.pydata.org/docs/reference/api/pandas.merge.html)

### 비율·기간·단위를 다루는 경우

- 비율: 분자와 분모가 같은 기간·대상 기준인지 확인한다. 분모가 0일 때의 표시도 정한다.
- 기간: 시작일·종료일의 포함 여부와 날짜/시간 구분을 확인한다.
- 단위: 원·천 원, 분·시간, 미터·킬로미터를 섞지 않았는지 확인한다.
- 반올림: 합산 전 반올림과 합산 후 반올림 중 업무 기준이 무엇인지 확인한다.

이 연결·비율·기간 사례는 기본 실습의 구현 범위 밖이다. 자신의 과제에 해당하는 경우 추가할 검증이다.

## 기록 예시

```text
검증 대상: 부서별 승인 금액 집계
입력: requests.csv 6건, 필터 품질
기대값과 근거: 승인 R003만 포함 → 1건·5,000원
실제값: 실행 후 직접 기록
판정: 통과 / 실패 / 미실행 중 실제 상태 선택
근거: 실행 명령, 결과 파일 또는 화면
문제와 다음 행동: 발견한 차이와 재검증 범위
```
