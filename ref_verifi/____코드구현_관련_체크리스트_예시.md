# 코드 구현 관련 체크리스트 예시 — Python 100항목

[전체 검증](일반적인_검증_체크리스트_예시.md) · [웹서버 검증](웹서버_관련_체크리스트_예시.md)

비개발자가 Codex에 확인을 요청할 때 사용할 후보 목록이다. 프로젝트에 맞는 항목을 골라 사용하며, 이 문서 자체는 검증 결과가 아니다.

- 각 항목은 실제 확인 후 통과·실패·검토만·미실행으로 기록한다. 적용되지 않으면 해당 없음(N/A)과 이유를 적는다.
- 코드·파일 수정과 실행은 현재 세션의 권한 및 승인된 실행 환경을 따른다. 모든 프로젝트에 100개를 강제로 적용하지 않는다.
- 기록 예: `PY-021 / 통과 / 입력 0·-1 / 기대: 0 허용·-1 거절 / 실제 결과와 실행 근거`.

## 사용 요청 예시

> 아래 100항목 중 내 Python 프로젝트에 해당하는 항목을 먼저 고르고, 확인 방법을 제시해. 실제 실행한 것과 코드만 검토한 것을 구분하고, 지적에는 파일·관련 위치·발생 조건·영향·개선안을 붙여줘. 권한 밖의 수정은 하지 마.

## 1. 함수의 입력·출력 약속

- [ ] PY-001 핵심 함수마다 대표 입력 1개를 넣고 반환값을 직접 확인한다. 예: 합계 함수가 출력만 하고 끝나지 않고 계산값을 반환하는지 확인.
- [ ] PY-002 함수 인자의 의미·자료형·단위가 호출부와 일치하는지 확인한다. 예: 초 단위 인자에 분 값을 그대로 전달하지 않음.
- [ ] PY-003 필수 인자를 빼고 호출했을 때 누락을 알리는 오류가 나는지 확인한다. 임의 기본값으로 정상 처리되지 않아야 하는 인자를 구분.
- [ ] PY-004 정상 분기마다 반환 구조를 비교한다. 예: 같은 함수가 어떤 경우에는 dict(키와 값을 묶은 자료), 다른 경우에는 문자열을 반환해 호출부가 깨지지 않음.
- [ ] PY-005 결과가 없는 정상 상황과 처리 실패를 구분한다. 예: 검색 결과 없음은 빈 목록, 파일 읽기 실패는 별도 오류로 표현.
- [ ] PY-006 기본 인자가 빈 목록·dict인 함수를 두 번 호출해 첫 호출의 내용이 다음 호출에 남지 않는지 확인한다.
- [ ] PY-007 입력 목록·dict를 함수 호출 전후 비교한다. 입력을 바꾸는 함수라는 약속이 없다면 원본 내용이 유지되어야 함.
- [ ] PY-008 같은 입력으로 함수를 다른 순서로 호출해 결과가 이전 호출의 전역 변수(여러 함수가 공유하는 값)에 의존하지 않는지 확인한다.
- [ ] PY-009 조건문·조기 종료 분기를 모두 따라가며 반환을 빠뜨린 경로를 찾는다. 의도하지 않은 None이 호출부로 전달되지 않아야 함.
- [ ] PY-010 계산 기능을 파일 읽기나 화면 출력 없이도 호출해 확인할 수 있는지 점검한다. 필요한 값을 인자로 넣어 결과를 비교할 수 있어야 함.

## 2. 입력 형식과 자료형 변환

- [ ] PY-011 목록을 받는 위치에 문자열·dict를 넣어 잘못된 자료형을 구분하는지 확인한다. 문자열의 글자를 데이터 행처럼 처리하지 않음.
- [ ] PY-012 None, 빈 문자열, 0, False를 각각 넣어 처리 결과를 비교한다. if not value 때문에 유효한 0까지 누락으로 취급하지 않음.
- [ ] PY-013 필수 키가 없는 dict를 넣어 누락 위치가 드러나는지 확인한다. get의 기본값이 필수 값 누락을 숨기지 않아야 함.
- [ ] PY-014 정수만 받는 값에 True·False를 넣어 허용 여부를 확인한다. 참·거짓을 1·0으로 처리해도 되는지 입력 규칙과 맞춤.
- [ ] PY-015 숫자 문자열의 공백·쉼표·부호 처리 기준을 확인한다. 예: " 1200 ", "1,200", "+1200"을 허용하거나 거절하는 방식이 일관적.
- [ ] PY-016 문자 식별자에 "0012"를 넣고 읽기·전달·저장 뒤에도 앞자리 0이 남는지 확인한다. 식별자를 무조건 int로 변환하지 않음.
- [ ] PY-017 숫자로 바꿀 수 없는 "abc"를 넣어 명시적인 오류가 나는지 확인한다. 변환 실패를 임의의 0으로 바꾸지 않음.
- [ ] PY-018 bytes(바이트 데이터)와 str(문자열)이 섞일 수 있는 입력에서 필요한 인코딩으로 변환하는지 확인한다. 디코딩 실패를 무시해 글자를 유실하지 않음.
- [ ] PY-019 예상하지 못한 추가 필드를 넣고 정책대로 처리되는지 확인한다. 오타 난 필드가 조용히 무시되어 필수 설정이 빠지지 않음.
- [ ] PY-020 중첩된 dict·목록에서 내부 항목이 없거나 형식이 틀린 입력을 넣는다. 최상위 자료형만 확인하고 내부 접근 중 뜻밖의 오류가 나지 않음.

## 3. 숫자·날짜의 경계 조건

- [ ] PY-021 최솟값과 그보다 작은 값을 각각 넣는다. 예: 0 이상 정수 조건이라면 0은 허용하고 -1은 거절.
- [ ] PY-022 최댓값과 그보다 큰 값을 각각 넣어 경계 포함 여부를 확인한다. 예: 최대 100개라면 100개 허용·101개 거절.
- [ ] PY-023 분모가 0인 입력을 넣어 정한 방식으로 처리되는지 확인한다. 나눗셈 오류나 무한대를 정상 결과로 내보내지 않음.
- [ ] PY-024 예상 범위를 넘는 큰 수를 넣어 변환·계산이 감당 가능한지 확인한다. int를 float나 제한된 숫자형으로 바꿀 때 값이 손상되지 않음.
- [ ] PY-025 float의 NaN(유효한 숫자가 아닌 값)·양의 무한대·음의 무한대를 넣어 허용하지 않는 곳에서 거절되는지 확인한다. 보통의 범위 비교만으로 놓치지 않음.
- [ ] PY-026 소수 계산의 비교 방식을 확인한다. 예: 0.1과 0.2를 더하는 계산에 무조건 정확한 float 동등 비교를 적용하지 않고 필요한 정밀도를 정함.
- [ ] PY-027 반올림 경계의 값을 넣고 정한 결과와 비교한다. 예: 2.5·3.5 처리와 중간 단계/최종 단계 중 반올림 위치를 확인.
- [ ] PY-028 존재하지 않는 날짜 문자열을 넣어 거절되는지 확인한다. 예: 2월 30일이 다른 날짜로 자동 보정되지 않음.
- [ ] PY-029 시간대가 있는 시각과 없는 시각이 섞일 때 처리 기준을 확인한다. 비교·정렬·시간 차이 계산 전에 같은 기준으로 맞춤.
- [ ] PY-030 윤년·월말을 포함한 날짜 계산을 확인한다. 예: 2월 28일 다음 날이나 월을 넘기는 기간을 고정 30일로 잘못 계산하지 않음.

## 4. 목록·dict·반복 처리

- [ ] PY-031 빈 목록과 원소 1개짜리 목록으로 실행해 첫 원소·마지막 원소 접근이 안전한지 확인한다.
- [ ] PY-032 range(반복 범위)·슬라이싱(일부 구간 추출)으로 구간을 처리할 때 첫 항목과 마지막 항목이 의도대로 포함되는지 확인한다. 마지막 한 건 누락 여부를 작은 입력으로 비교.
- [ ] PY-033 반복 중인 목록에서 항목을 삭제·추가하는 코드가 있다면 연속된 대상 두 개로 확인한다. 다음 항목을 건너뛰지 않아야 함.
- [ ] PY-034 중복 원소를 포함한 목록을 넣어 필요한 중복이 보존되는지 확인한다. 단순 편의를 위해 set(중복 없는 집합)으로 바꾸며 데이터를 줄이지 않음.
- [ ] PY-035 목록을 dict로 변환할 때 같은 키가 두 번 등장하는 사례를 넣는다. 이전 값 덮어쓰기가 허용되지 않는 용도라면 중복을 알림.
- [ ] PY-036 정렬 기준값이 같은 항목들을 넣고 순서가 요구한 기준대로 결정되는지 확인한다. 필요한 경우 보조 정렬 기준을 명시.
- [ ] PY-037 길이가 다른 두 목록을 함께 처리해 누락을 알아내는지 확인한다. zip(여러 목록을 함께 순회하는 기능)이 짧은 목록 길이에 맞춰 끝나도 괜찮은지 점검.
- [ ] PY-038 중첩 목록의 한 칸을 바꿨을 때 다른 행까지 바뀌지 않는지 확인한다. 같은 내부 목록을 여러 번 참조하는 생성 방식을 점검.
- [ ] PY-039 generator·iterator(한 번씩 소비하며 읽는 입력)를 여러 곳에서 읽는 코드가 있으면 두 번째 읽기도 확인한다. 이미 소비한 입력을 빈 입력으로 오인하지 않음.
- [ ] PY-040 while문과 페이지·묶음 반복 처리에 종료 조건이 있는지 확인한다. 빈 결과나 진전 없는 결과가 반복돼도 무한 반복하지 않음.

## 5. 예외 처리와 로그

- [ ] PY-041 예상 가능한 잘못된 입력을 넣어 알맞은 예외나 오류 결과가 나오는지 확인한다. except 뒤 pass로 실패를 숨기지 않음.
- [ ] PY-042 try 범위에 무관한 작업이 함께 들어 있는지 확인한다. 파일 없음 처리에 계산 버그까지 묻혀 잘못된 원인으로 보고되지 않음.
- [ ] PY-043 오류 메시지에 고칠 수 있는 정보가 있는지 확인한다. 예: "입력 오류"만 쓰지 않고 문제가 난 필드명·행 위치를 알림.
- [ ] PY-044 실패한 작업이 정상 종료 코드나 정상 결과값을 반환하지 않는지 확인한다. 상위 실행기가 실패를 알아낼 수 있어야 함.
- [ ] PY-045 예외를 다른 예외로 바꿀 때 원인과 추적 정보가 남는지 확인한다. 재현·수정에 필요한 최초 오류가 사라지지 않음.
- [ ] PY-046 여러 파일·행을 처리하다 일부가 실패하는 입력을 넣는다. 성공·실패 항목을 구분하고 전체 성공으로 보고하지 않음.
- [ ] PY-047 재시도가 있다면 일시적 실패와 입력 오류를 구분하는지 확인한다. 바뀌지 않을 잘못된 입력을 반복 요청하지 않음.
- [ ] PY-048 finally(마지막 정리 구간) 안의 return이나 새 예외 때문에 원래 실패가 가려지지 않는지 확인한다. 실패 조건에서 호출부가 받는 결과를 직접 확인.
- [ ] PY-049 성공 로그가 실제 작업 완료 이후에 기록되는지 확인한다. 파일 저장 전에 "저장 완료"를 출력하지 않음.
- [ ] PY-050 대량 오류 상황에서 로그가 필요한 진단 정보를 남기는지 확인한다. 같은 오류를 끝없이 출력하기보다 대상·건수·대표 원인을 식별 가능하게 기록.

## 6. 파일·경로·인코딩

- [ ] PY-051 실행하는 현재 폴더를 바꿔도 입력 파일을 찾는지 확인한다. 프로젝트 기준 경로인지 실행 위치 기준 경로인지 코드와 안내를 맞춤.
- [ ] PY-052 한글과 공백이 포함된 폴더·파일명으로 읽기·쓰기를 확인한다. 경로를 공백으로 잘라 파일을 잘못 찾지 않음.
- [ ] PY-053 파일 경로 자리에 폴더를 넣거나 그 반대인 경우를 확인한다. 존재 여부만 검사하지 않고 파일/폴더 종류를 구분.
- [ ] PY-054 없는 입력 파일로 실행해 필요한 파일과 위치를 알려주는지 확인한다. 빈 결과 파일을 만들어 정상 처리처럼 보이게 하지 않음.
- [ ] PY-055 출력의 부모 폴더가 없을 때 생성하거나 명확히 오류를 내는지 확인한다. 생성은 허용된 프로젝트 경로 안에서 수행.
- [ ] PY-056 한글 텍스트·CSV를 저장한 뒤 다시 읽어 원문과 비교한다. 사용 환경에 맞는 인코딩을 명시하고 필요하면 UTF-8 BOM을 적용.
- [ ] PY-057 쉼표·따옴표·줄바꿈이 들어 있는 CSV 셀을 왕복 저장·읽기한다. split으로 임의 분리하지 않고 셀 내용이 유지되는지 확인.
- [ ] PY-058 JSON으로 저장하는 날짜·소수·특수 자료형의 변환 기준을 확인한다. 저장·재입력 뒤 필요한 자료형과 값이 복구되는지 비교.
- [ ] PY-059 사용자가 입력한 경로에 상위 폴더 이동이나 절대 경로가 들어간 경우를 확인한다. 실제 해석된 경로가 허용 영역 밖이면 쓰기·삭제를 막음.
- [ ] PY-060 입력과 출력이 같은 파일을 가리키는지 저장 전에 확인한다. 원본 보존이 필요한 작업에서 다른 경로 표기로 같은 파일을 덮어쓰지 않음.

## 7. 자원 정리와 부작용

- [ ] PY-061 파일을 처리하다 오류가 나도 열린 파일이 닫히는지 확인한다. with 문 등 정리 경로를 사용하고 재열기·이동이 막히지 않는지 점검.
- [ ] PY-062 임시 파일·폴더가 작업별로 구분되고 종료 후 정리되는지 확인한다. 정리 대상은 이번 작업이 만든 경로로 한정.
- [ ] PY-063 다른 프로그램이 표준출력을 읽는 경우 결과와 진행 로그가 섞이지 않는지 확인한다. 예: JSON 출력 앞에 디버그 문장이 붙지 않음.
- [ ] PY-064 기존 결과 파일을 교체하다 중단되는 상황을 확인한다. 필요하면 임시 파일 저장 후 교체해 이전 정상 파일이 반쯤 덮이지 않게 처리.
- [ ] PY-065 외부 명령 실행 후 종료 코드를 검사하는지 확인한다. 명령 실패를 무시하고 다음 단계나 완료 메시지로 넘어가지 않음.
- [ ] PY-066 외부 명령에 한글·공백·따옴표가 포함된 인자를 전달해 확인한다. 입력을 셸 명령 문자열에 무작정 이어 붙이지 않음.
- [ ] PY-067 외부 프로세스가 멈추거나 시간이 초과되면 정리되는지 확인한다. 종료·회수 처리를 두고 시험 실행의 자식 프로세스를 남기지 않음.
- [ ] PY-068 DB 쓰기가 여러 단계라면 중간 실패 시 일관된 상태로 남는지 확인한다. 함께 성공해야 하는 변경은 트랜잭션(묶음 처리)·롤백(실패 시 되돌리기) 기준을 적용.
- [ ] PY-069 여러 스레드·프로세스가 같은 상태나 파일을 바꾸는 경우 동시 실행을 확인한다. 갱신 누락·내용 혼합·덮어쓰기를 막는 처리가 있어야 함.
- [ ] PY-070 같은 작업을 두 번 실행했을 때 결과를 비교한다. 덧붙이기·교체·건너뛰기 중 의도한 동작이며 중복 저장이 뜻밖에 발생하지 않음.

## 8. 실행 환경과 의존성

- [ ] PY-071 실행 전에 사용하는 Python 경로를 확인한다. 승인된 프로젝트 가상환경 등 지정 환경을 사용하고 시스템 전역 환경으로 바뀌지 않음.
- [ ] PY-072 프로젝트가 요구하는 Python 버전에서 문법과 표준 라이브러리 기능을 사용할 수 있는지 확인한다. 개발 PC에서만 가능한 기능을 무심코 사용하지 않음.
- [ ] PY-073 외부 패키지 import(다른 모듈 불러오기)를 점검해 필요한 의존성이 설치 목록에 있는지 확인한다. 코드에 쓰지 않는 패키지를 불필요하게 필수로 만들지 않음.
- [ ] PY-074 같은 가상환경에서 의존성 버전 충돌을 확인한다. 설치에 성공했다는 이유만으로 서로 호환된다고 가정하지 않음.
- [ ] PY-075 깨끗한 가상환경에서 명시된 의존성만으로 시작할 수 있는지 확인한다. 다른 프로젝트에서 우연히 설치한 패키지에 의존하지 않음.
- [ ] PY-076 사용자 이름·드라이브 문자·로컬 절대 경로가 코드에 고정되어 있는지 확인한다. 다른 PC에서도 설정이나 프로젝트 기준 경로로 바꿀 수 있어야 함.
- [ ] PY-077 필수 환경 변수를 빼고 실행해 누락을 알려주는지 확인한다. 임의 기본값으로 다른 데이터·다른 환경을 처리하지 않음.
- [ ] PY-078 비밀번호·API 키 같은 비밀값이 코드·설정 예시·로그·결과 파일에 그대로 남지 않는지 확인한다. 진단 출력에서도 필요한 부분만 표시.
- [ ] PY-079 안내한 진입점과 실행 방식으로 import가 해결되는지 확인한다. 스크립트 직접 실행과 패키지 실행 중 어떤 방식이 필요한지 명확하게 안내.
- [ ] PY-080 프로젝트 코드가 .venv 안에 저장되어 있지 않은지 확인한다. 실행 환경을 새로 만들어도 소스·입력 자료·설정 예시는 남아 있어야 함.

## 9. 코드 구조와 실행 비용

- [ ] PY-081 모듈을 import만 했을 때 파일 변경·긴 계산·외부 작업이 시작되지 않는지 확인한다. 실제 실행 진입점과 재사용 함수의 동작을 구분.
- [ ] PY-082 서로 import하는 모듈을 처음 불러오는 상황을 확인한다. 초기화 순서 때문에 일부 함수·값을 찾지 못하는 순환 참조가 없는지 점검.
- [ ] PY-083 파일명이 Python 표준 모듈·사용 패키지와 충돌하는지 확인한다. 예: json.py·inspect.py 때문에 원래 모듈 대신 내 파일을 읽지 않음.
- [ ] PY-084 동일한 함수·설정이 여러 번 정의되어 앞의 정의가 덮이는지 확인한다. 실제로 호출되는 구현을 추적할 수 있어야 함.
- [ ] PY-085 여러 곳에 복사된 핵심 입력 검사·변환 규칙을 비교한다. 같은 입력이 호출 경로에 따라 다르게 처리되면 기준을 맞추거나 공통화.
- [ ] PY-086 실제 입력을 바꿔 실행해 결과가 함께 바뀌는지 확인한다. 임시 상수·시연용 데이터·고정된 예시 결과가 본 코드에 남지 않음.
- [ ] PY-087 현재 실행 경로에 TODO·pass·임시 반환값이 남았는지 확인한다. 미구현 기능을 정상 성공처럼 표시하지 않음.
- [ ] PY-088 함수의 자료형 설명과 실제 인자·반환값을 비교한다. 타입 힌트(값의 자료형 설명)가 있다는 사실만으로 실행 중 입력 검사가 된 것으로 판단하지 않음.
- [ ] PY-089 반복문 안에서 같은 파일 읽기·같은 계산을 되풀이하는지 확인한다. 대표 입력으로 시간을 측정하고 병목이 확인된 부분부터 줄임.
- [ ] PY-090 큰 입력에서 메모리 사용과 처리 제한을 확인한다. 전체 파일을 여러 복사본으로 보관하는 대신 필요한 경우 묶음 처리나 입력 크기 제한을 적용.

## 10. 테스트와 수정 후 재검증

- [ ] PY-091 핵심 함수의 기대값을 요구사항·손계산·검증된 작은 사례에서 정한다. 현재 구현의 출력값을 그대로 정답으로 복사하지 않음.
- [ ] PY-092 테스트가 결과값이나 중요한 상태를 비교하는지 확인한다. 예외가 안 났다는 사실이나 값이 존재한다는 사실만 검사하고 끝내지 않음.
- [ ] PY-093 실패 입력 테스트에서 기대하는 예외 종류·오류 내용을 확인한다. 어떤 오류든 발생하면 통과하도록 만들어 무관한 버그를 숨기지 않음.
- [ ] PY-094 고위험 조건의 정상값·경계값·잘못된 값을 각각 테스트한다. 예: 허용 범위 안 숫자, 경계 0, 범위 밖 -1을 별도 사례로 확인.
- [ ] PY-095 테스트 순서를 바꾸거나 하나씩 실행해도 결과가 유지되는지 확인한다. 앞 테스트의 파일·전역 상태·모의 객체(테스트용 대체 객체)가 다음 테스트에 남지 않음.
- [ ] PY-096 현재 시각·난수에 의존하는 테스트의 재현 방법을 확인한다. 필요하면 시각·난수 입력을 고정하거나 허용 범위·성질을 검사.
- [ ] PY-097 테스트용 파일과 결과 경로를 실제 원본과 분리한다. 실행 전후 원본이 변경되지 않았고 테스트 데이터만 정리되는지 확인.
- [ ] PY-098 테스트가 실제 프로젝트 함수를 import해 호출하는지 확인한다. 테스트 파일 안에 비슷한 함수를 다시 만들어 그것만 검사하지 않음.
- [ ] PY-099 발견한 버그를 재현하는 입력을 테스트로 남기고 수정 후 다시 실행한다. 수정 이전의 실패 조건이 실제로 해결됐는지 확인.
- [ ] PY-100 최신 코드로 실행한 테스트 수·실패·오류·건너뜀과 종료 코드를 확인한다. 실행 대상 0개나 미실행을 통과로 보고하지 않고 실행 명령·근거를 남김.
