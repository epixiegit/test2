# 일반적인 검증 체크리스트 예시 — 문제해결·분석 측면

- 총 100개 항목, 10개 영역. 코드 문법보다 **올바른 문제를 풀었는지, 데이터와 판단 근거가 맞는지**를 확인하는 목록.
- 아래는 직접 구성한 실무 예시이며 대회의 공식 채점표가 아님. 과제와 관련된 항목을 골라 적용하고, 전부 검사하려고 범위를 늘리지 않기.
- 확인하고 통과한 항목만 체크. 관련 없으면 `N/A + 이유`, 확인 못 했으면 `미확인 + 이유`, 틀렸으면 `실패 + 수정할 내용`을 해당 항목 뒤에 기록.
- 근거는 짧게 붙이기: `기대 35,000원 / 실제 35,000원 / 근거: 결과.csv, 손계산 6행`. 이 문서는 실행 결과가 아니라 검증할 질문 목록.

## 1. 문제와 현업 맥락 확인

- [ ] ANA-001 해결 대상 사용자를 특정했는가? 예: ‘회사 직원 전체’ 대신 ‘매일 구매 요청을 취합하는 담당자’처럼 실제 업무 수행자를 적는다.
- [ ] ANA-002 문제를 기능 이름 없이 설명했는가? ‘대시보드가 없다’가 아니라 ‘취소 건이 집계에 섞여 결재 금액을 다시 계산한다’처럼 불편과 손실을 적는다.
- [ ] ANA-003 현업의 실제 사례를 최소 1건 확보했는가? 어떤 입력에서 어떤 결과가 잘못됐는지 원본 행·문서·대화 근거로 확인한다.
- [ ] ANA-004 문제의 빈도와 영향 규모를 확인했는가? 주 1회인지 매일인지, 소요 시간·오류 건수는 측정값인지 추정값인지 구분한다.
- [ ] ANA-005 현재 업무의 시작부터 끝까지 흐름을 확인했는가? 입력 수집 → 담당자 판단 → 처리 → 보고 중 무엇을 개선할지 표시한다.
- [ ] ANA-006 가장 큰 지연이나 재작업이 발생하는 구간을 찾았는가? 전체 과정이 느리다는 표현 대신 대기·확인·재입력 중 병목을 특정한다.
- [ ] ANA-007 관찰한 증상과 원인 가설을 구분했는가? ‘처리가 늦다’는 사실만으로 ‘인력이 부족하다’를 확정하지 않는다.
- [ ] ANA-008 관련 담당자들의 요구가 충돌하는지 확인했는가? 속도·정확성·비용 중 무엇을 우선할지 결정권자에게 확인한다.
- [ ] ANA-009 과제 README·참고자료·현업 답변의 요구가 서로 일치하는가? 다른 내용이 있으면 충돌 지점과 적용 기준을 남긴다.
- [ ] ANA-010 답을 모르는 핵심 질문을 목록으로 남겼는가? 특히 답에 따라 집계 기준이나 해결 방향이 바뀌는 질문부터 확인한다.

## 2. 목표·범위·성공 기준 확인

- [ ] ANA-011 개선 전 상태를 같은 기준으로 측정했는가? ‘30분에서 10분으로 단축’이라면 기존 30분의 측정 범위와 근거를 확인한다.
- [ ] ANA-012 목표를 관찰 가능한 지표로 표현했는가? ‘편리하게’ 대신 처리 시간·오류 건수·누락률처럼 결과를 확인할 수 있는 지표를 쓴다.
- [ ] ANA-013 목표값의 근거가 있는가? 사용자의 요구·현재 수준·가용 시간과 무관하게 100% 정확도나 과도한 개선율을 약속하지 않는다.
- [ ] ANA-014 통과·실패를 가르는 허용 오차를 정했는가? 금액은 원 단위 일치, 거리 추정은 합의한 오차 이내처럼 지표별 기준을 명시한다.
- [ ] ANA-015 시간·예산·사용 가능한 도구·데이터 접근 범위를 확인했는가? 해결안이 실제 실행 환경에서 지킬 수 있는 제약인지 점검한다.
- [ ] ANA-016 반드시 완성해야 하는 핵심 업무 흐름을 정했는가? 입력부터 필요한 결과까지 이어지는 최소 범위를 실제 사용자 행동으로 적는다.
- [ ] ANA-017 이번에 만들지 않을 범위를 명시했는가? 예: 과제에 필요 없는 로그인·실시간 연동·관리자 기능을 제외했다고 기록한다.
- [ ] ANA-018 최종 산출물의 형태를 확인했는가? 웹 화면·분석표·CSV·설명 문서 중 무엇을 어떤 경로와 이름으로 내야 하는지 정한다.
- [ ] ANA-019 완료를 누가 어떤 사례로 확인할지 정했는가? ‘현업이 승인 요청을 조회해 합계를 대조한다’처럼 수용 확인 절차를 적는다.
- [ ] ANA-020 진행 중 요구가 바뀌었을 때 기준도 함께 갱신했는가? 바뀐 조건과 변경 전 결과의 사용 가능 여부를 기록한다.

## 3. 해결안 선택과 판단 근거 검토

- [ ] ANA-021 현재 방식을 유지했을 때의 비용과 위험을 비교했는가? 새 도구를 만드는 편익이 문제 규모에 비해 충분한지 확인한다.
- [ ] ANA-022 코드 작성 없이 해결할 방법도 검토했는가? 입력 양식 통일·업무 규칙 정리·기존 Excel 기능만으로 충분한 경우를 비교한다.
- [ ] ANA-023 가능한 대안을 둘 이상 같은 기준으로 비교했는가? 기능 개수 대신 정확도·구현 시간·유지 부담 등 공통 기준을 쓴다.
- [ ] ANA-024 선택한 기능이 확인된 원인을 직접 줄이는가? 원인이 기준 불일치인데 시각화만 추가하는 식의 연결 단절을 확인한다.
- [ ] ANA-025 만드는 시간뿐 아니라 사용하는 사람의 추가 작업도 계산했는가? 매번 수동 복사·열 이름 수정이 필요한지 확인한다.
- [ ] ANA-026 외부 서비스·담당자·승인에 대한 의존성을 확인했는가? 당일 확보할 수 없는 API 키나 계정 없이는 동작하지 않는지 살핀다.
- [ ] ANA-027 해결안에 필요한 데이터가 실제로 있는가? 존재하지 않는 이력·실시간 위치·개인 정보를 있다고 가정하지 않는다.
- [ ] ANA-028 핵심 방법이 실패했을 때 대체 경로가 있는가? 자동 추천 실패 시 원본 목록 조회나 수동 판단으로 이어질 수 있는지 확인한다.
- [ ] ANA-029 개선으로 새롭게 생기는 손실이나 편향을 검토했는가? 비용 절감 때문에 특정 부서의 대기 시간만 늘어나지 않는지 확인한다.
- [ ] ANA-030 대안을 채택·기각한 이유가 남아 있는가? ‘AI가 추천했다’가 아니라 실제 제약·비교 결과와 연결해 설명한다.

## 4. 데이터의 의미와 분석 대상 확인

- [ ] ANA-031 사용할 원본 파일·시트·테이블의 목록을 확보했는가? 누락된 월별 파일이나 사용하지 않은 참고자료가 있는지 확인한다.
- [ ] ANA-032 원본의 작성일·갱신일·버전을 확인했는가? 서로 다른 시점의 직원 명부와 구매 내역을 최신 자료로 혼동하지 않는다.
- [ ] ANA-033 한 행이 무엇을 뜻하는지 확인했는가? 요청 1건인지, 요청에 포함된 품목 1개인지에 따라 건수와 합계가 달라진다.
- [ ] ANA-034 행을 구별할 식별자와 업무상 유일성 기준을 정했는가? 주문번호만 유일한지, 주문번호와 품목번호 조합이 유일한지 확인한다.
- [ ] ANA-035 숫자 열의 단위를 확인했는가? 원·천 원, 분·시간, 미터·킬로미터, 세전·세후 금액이 섞이지 않는지 살핀다.
- [ ] ANA-036 날짜·시간의 의미를 확인했는가? 요청일·승인일·결제일 중 어느 날짜로 기간을 나누는지와 시간대를 정한다.
- [ ] ANA-037 상태값의 의미와 처리 범위를 확인했는가? 승인·취소·반려·진행 중을 어떤 지표에 포함할지 현업 기준과 맞춘다.
- [ ] ANA-038 코드표와 이름의 대응 관계를 확인했는가? 같은 부서 코드가 서로 다른 이름으로 나타나거나 개편 전후 코드가 섞이는지 확인한다.
- [ ] ANA-039 데이터가 포함하는 기간·지역·대상자를 확인했는가? 제공된 일부 공장 자료로 회사 전체의 결과를 주장하지 않는다.
- [ ] ANA-040 개인 정보의 포함 여부를 확인하고 필요한 처리 기준을 정했는가? 결과 공유에 이름·연락처가 꼭 필요한지 확인하고 식별자 대체나 제외 기준을 정한다.

## 5. 원본 데이터 품질 점검

- [ ] ANA-041 열별 빈값과 누락률을 확인했는가? 전체뿐 아니라 부서·기간별 누락이 특정 집단에 집중되는지도 확인한다.
- [ ] ANA-042 완전 중복 행과 업무상 반복 거래를 구분했는가? 같은 금액·날짜라는 이유만으로 실제 별도 요청을 삭제하지 않는다.
- [ ] ANA-043 식별자의 형식을 유지했는가? 직원번호 ‘00123’이 숫자 123으로 바뀌어 다른 파일과 연결되지 않는지 확인한다.
- [ ] ANA-044 숫자가 업무상 가능한 범위에 있는가? 음수 재고·100% 초과 비율이 오류인지 반품·중복 집계 등 설명 가능한 값인지 확인한다.
- [ ] ANA-045 날짜가 실제로 존재하며 분석 기간에 맞는가? 잘못된 날짜·미래 날짜·연도 오기가 섞였는지 확인한다.
- [ ] ANA-046 범주 표기 차이의 의미와 처리 기준을 확인했는가? ‘품질’, ‘품질팀’, ‘품질 ’을 합칠지 실제로 다른 조직인지 확인한다.
- [ ] ANA-047 유난히 큰 값이나 작은 값을 원본과 대조했는가? 이상치를 오류로 단정하지 말고 대량 주문 같은 실제 사건인지 확인한다.
- [ ] ANA-048 같은 행의 값끼리 모순이 없는가? 종료일이 시작일보다 빠르거나 취소 상태인데 취소 사유가 없는 경우의 의미를 확인한다.
- [ ] ANA-049 다른 표를 참조하는 값이 실제 존재하는가? 직원의 부서 코드가 부서 목록에 없으면 미연결 건수와 영향을 확인한다.
- [ ] ANA-050 기록된 대상과 빠진 대상의 차이를 살폈는가? 성공한 요청만 저장된 자료로 실패율이나 전체 처리 시간을 추정하지 않는다.

## 6. 정제·병합·필터 처리 검토

- [ ] ANA-051 원본과 가공 결과를 구분해 보관했는가? 정제 후에도 어떤 원본 행이 바뀌었는지 돌아가 확인할 수 있어야 한다.
- [ ] ANA-052 자료형 변환 과정에서 손실된 값을 집계했는가? ‘미정’이나 쉼표 포함 금액이 숫자로 바뀌지 못해 빠진 건수를 확인한다.
- [ ] ANA-053 누락값 처리 근거를 정했는가? 알 수 없는 금액을 0원으로 채웠다면 합계를 낮추는 영향과 그 판단 이유를 검토한다.
- [ ] ANA-054 중복 제거 시 남기는 행을 정했는가? 최초 접수·최신 수정 중 어느 기록을 남길지와 버린 행 수를 확인한다.
- [ ] ANA-055 취소·정정·재승인 이력을 분석 기준시점과 지표 정의에 맞게 처리했는가? 현재 상태·특정 시점의 상태·상태 변경 건수를 구분하고 중복 계산을 확인한다.
- [ ] ANA-056 표를 합칠 때 연결 관계를 확인했는가? 직원 1명에 부서 1개를 붙이려는데 부서표 중복 때문에 행이 늘어나지 않는지 살핀다.
- [ ] ANA-057 병합되지 않은 행을 별도로 확인했는가? 코드 불일치로 제외된 직원·거래가 조용히 사라지지 않도록 건수와 사유를 남긴다.
- [ ] ANA-058 병합 전후의 행 수와 핵심 금액을 비교했는가? 품목표와 주문표를 합친 뒤 주문 총액이 품목 수만큼 반복 합산되지 않는지 확인한다.
- [ ] ANA-059 공통 비용이나 중복 소속을 나누는 기준이 있는가? 여러 부서에 나누어 배정한 금액의 합이 원래 금액과 일치하는지 확인한다.
- [ ] ANA-060 필터 적용 전후의 대상 수가 설명되는가? 포함 건수와 제외 건수의 합이 원본과 맞고, 각 제외 사유를 확인할 수 있어야 한다.

## 7. 지표·집계 정의 점검

- [ ] ANA-061 비율의 분자와 분모가 같은 대상을 가리키는가? 승인 건수는 이번 달인데 전체 요청 수는 누적값인 식의 혼용을 확인한다.
- [ ] ANA-062 행 수와 고유 대상 수를 구분했는가? 한 직원이 여러 번 이용한 기록에서 이용 건수와 이용자 수를 별도로 계산한다.
- [ ] ANA-063 평균의 가중치가 맞는가? 부서별 인원이 다를 때 부서 평균을 단순 평균한 값이 전체 직원 평균과 같다고 보지 않는다.
- [ ] ANA-064 분모가 0인 비율의 표시 기준을 정했는가? 요청이 없는 부서의 승인율을 0%로 볼지 ‘산출 불가’로 표시할지 정한다.
- [ ] ANA-065 증감률과 퍼센트포인트를 구분했는가? 20%에서 30%로 바뀐 것을 10%p 상승과 50% 상대 증가 중 무엇으로 설명하는지 확인한다.
- [ ] ANA-066 누적값·기간 발생량·시점 잔액을 구분했는가? 매일의 재고 잔액을 더해 월간 입고량으로 표시하지 않는다.
- [ ] ANA-067 기간 경계의 포함 기준이 명확한가? 월말·자정·마감 시각의 거래가 두 기간에 중복되거나 모두 빠지지 않는지 확인한다.
- [ ] ANA-068 반올림 시점과 소수 자릿수를 정했는가? 개별 행에서 반올림한 합과 최종 합계에서 반올림한 값이 다를 때 적용 기준을 확인한다.
- [ ] ANA-069 전후 비교에서 대상 집단과 집계 기준이 같은가? 부서가 추가됐거나 상태 정의가 바뀐 효과를 개선 성과로 오해하지 않는다.
- [ ] ANA-070 부서나 범주가 없는 행의 집계 위치를 정했는가? ‘미지정’으로 따로 셀지 제외할지 정하고 전체 합계와 차이를 설명한다.

## 8. 계산 결과와 방법의 타당성 확인

- [ ] ANA-071 작은 데이터의 정답을 계산 전에 직접 만들었는가? 승인 5건·35,000원처럼 원본 몇 행으로 기대 결과를 설명한다.
- [ ] ANA-072 중요 결과를 독립적인 방법으로 대조했는가? AI 결과를 그대로 정답으로 복사하지 말고 손계산·원장·별도 계산식과 비교한다.
- [ ] ANA-073 합산 가능한 지표에서 세부 결과의 합이 전체와 맞는가? 금액처럼 더할 수 있는 값은 같은 범위에서 대조하고, 평균·비율·중복 가능한 고유 대상 수는 각각의 집계 정의로 확인한다.
- [ ] ANA-074 업무상 반드시 지켜야 할 관계를 만족하는가? 배정 인원은 대상 인원 이하이고 지출은 예산 이하여야 한다는 조건 등을 확인한다.
- [ ] ANA-075 경계 사례에서도 업무 규칙이 맞는가? 데이터 0건·1건, 금액 0원, 기준값과 같은 값의 결과를 미리 정하고 대조한다.
- [ ] ANA-076 입력 순서를 바꿔도 순서와 무관한 결과는 같은가? 파일 행을 재정렬했더니 총액이나 동일 조건의 순위가 달라지지 않는지 확인한다.
- [ ] ANA-077 새 데이터의 영향이 예상과 맞는가? 승인 요청 1,000원을 추가하면 해당 부서와 전체 금액만 1,000원 증가하는지 확인한다.
- [ ] ANA-078 같은 조건에서 결과를 다시 얻을 수 있는가? 무작위 추출이나 모델 호출이 포함되면 바뀔 수 있는 부분과 고정한 조건을 기록한다.
- [ ] ANA-079 배정·추천·최적화 결과가 실제 제약을 지키는가? 정원·운영 시간·거리 제한 등 필수 조건을 위반한 해를 좋은 점수로 채택하지 않는다.
- [ ] ANA-080 복잡한 방법을 단순한 기준선과 비교했는가? 기존 방식·기본 정렬·단순 평균보다 좋아진 점이 목표 지표에서 확인되는지 살핀다.

## 9. 결론의 신뢰성과 반례 검토

- [ ] ANA-081 극단적인 소수 사례가 결론을 좌우하는지 확인했는가? 해당 사례를 포함·제외한 결과를 비교하고 제거 여부의 근거를 남긴다.
- [ ] ANA-082 가정이나 기준값 변화에 따른 민감도를 확인하고 영향을 설명했는가? 허용 거리·가중치·목표값을 바꿔 결론이 유지되거나 뒤집히는 조건을 확인한다.
- [ ] ANA-083 집단별 악화 여부를 확인하고 영향을 평가했는가? 부서·시간대·지역별 결과를 나눠 전체 평균에 가려진 개선과 손실이 있는지 확인한다.
- [ ] ANA-084 관측 건수가 적은 집단을 과신하지 않았는가? 1건 중 1건 성공한 100%와 1,000건 중 990건 성공한 99%의 근거 강도를 구분한다.
- [ ] ANA-085 함께 변한 현상을 원인·결과로 단정하지 않았는가? 도구 도입 후 시간이 줄었어도 물량 감소나 인력 증가 영향을 함께 검토한다.
- [ ] ANA-086 예측 시점에 알 수 없는 정보를 사용하지 않았는가? 승인 여부를 예측하면서 승인 후에만 생기는 처리 결과를 입력으로 쓰지 않는다.
- [ ] ANA-087 예측 모델이나 규칙을 평가한 자료가 개발 자료와 적절히 분리됐는가? 미래 예측이면 시간 순서와 동일 고객의 중복 유입 등을 검토한다.
- [ ] ANA-088 추정 결과의 불확실성을 표현했는가? 실제 측정값과 가정 기반 절감액을 구분하고, 가능하면 조건별 범위나 시나리오를 제시한다.
- [ ] ANA-089 AI가 추출·요약·분류한 핵심 정보를 원문과 대조했는가? 금액·날짜·정책 예외처럼 결론에 영향이 큰 항목과 애매한 사례부터 확인한다.
- [ ] ANA-090 결론에 반하는 증거도 검토했는가? 실패 사례나 현업의 반대 답변을 제외하지 말고 해결 방향을 바꿔야 할 조건을 정리한다.

## 10. 결과 전달·업무 적용·최종 확인

- [ ] ANA-091 표와 차트에 단위·기간·대상·축 기준이 표시됐는가? 잘린 축이나 다른 축척 때문에 작은 차이가 과장되지 않는지 확인한다.
- [ ] ANA-092 보는 결과에 적용된 조건을 알 수 있는가? 선택한 부서·기간·취소 제외 여부가 화면이나 보고서에 명확히 나타나는지 확인한다.
- [ ] ANA-093 보고서·화면·다운로드 파일의 숫자가 같은 기준인가? 동일한 필터로 만든 결과인데 총액이나 대상 수가 다른지 대조한다.
- [ ] ANA-094 확정 사실·가정·추정·제안을 구분해 썼는가? 현업이 말하지 않은 기준이나 AI의 제안을 합의 사항처럼 표현하지 않는다.
- [ ] ANA-095 결과가 실제 의사결정으로 이어지는가? ‘품질팀의 누락률이 높다’에서 끝내지 않고 어떤 확인·조치를 할지 제시한다.
- [ ] ANA-096 도입 후 누가 언제 무엇을 할지 정했는가? 입력 갱신·오류 수정·결과 확인 담당자와 업무 흐름이 설명되는지 확인한다.
- [ ] ANA-097 다른 사람이 이어서 판단할 자료가 있는가? 사용한 원본·집계 규칙·주요 결정 이유·남은 질문을 찾아볼 수 있게 정리한다.
- [ ] ANA-098 중요 주장마다 확인 근거를 찾을 수 있는가? 요구사항 → 결과 → 검증 기록이 연결되고 미실행 항목을 통과로 표시하지 않는다.
- [ ] ANA-099 AI 없이도 핵심 선택을 설명할 수 있는가? 왜 이 문제·지표·방법을 골랐는지, 어디서 실패하는지 본인 산출물 기준으로 말해본다.
- [ ] ANA-100 입력·규칙·해결안을 마지막으로 바꾼 뒤 재확인했는가? 수정 전 검증 기록을 그대로 쓰지 말고 영향받은 결과와 연결된 흐름을 다시 확인한다.
