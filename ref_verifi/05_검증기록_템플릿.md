# 검증 기록 템플릿

[처음으로](README.md) · [검증 순서](01_검증순서_체크리스트.md) · [웹서버 검증](03_웹서버검증_예시.md)

> 실제 프로젝트에서 필요한 항목만 남겨 사용. 아래 행은 모두 **미실행** 상태이며, 작성된 기대값은 실행 증거가 아님.
> 이 폴더의 실습 결과를 실제 해커톤 프로젝트의 검증 결과로 옮겨 적지 않기.

## 1. 이번 검증의 기준

- 프로젝트·기능:
- 확인하려는 업무 목표:
- 요구사항·성공 기준의 출처: 문서 경로·구간 또는 현업에게 확인한 답변
- 검토 기준: Git 커밋 또는 파일·수정 시각
- 입력 데이터: 파일 경로·버전·행 수
- 실행 시각:
- 실행 환경: OS, 실제 Python/Node 경로·버전, 가상환경, 주요 패키지 버전
- 실제 접속 주소·포트: 로컬 주소인지 웹 IDE 미리보기인지 구분
- 실행 담당: 사람 / AI
- 결과를 확인한 사람:
- 이번 범위에 포함하지 않은 기능과 이유:

## 2. 판정 의미

| 상태 | 언제 쓰나 |
| --- | --- |
| PASS | 해당 입력으로 실제 실행했고, 정해둔 기대값과 실제 결과가 일치. 증거 위치를 남김 |
| FAIL | 실제 실행했으며 기대값과 실제 결과가 다름 |
| BLOCKED | 필요한 데이터·접속·환경 등이 없어 실행을 완료하지 못함. 막힌 이유를 남김 |
| NOT_RUN | 아직 실행하지 않음. 코드 검토나 테스트 제안만 한 경우도 실행 여부는 이 상태 |

- 코드 검토로 발견한 문제는 **‘검토 의견’**에 기록. 실행하지 않은 테스트를 PASS로 바꾸지 않기.
- 기능이 없어서 범위에서 제외한 항목은 삭제하거나 비고에 ‘범위 제외’를 표시. 통과 개수에 포함하지 않기.
- 일부 테스트 통과를 ‘프로젝트 전체 검증 완료’로 확대하지 않기.

## 4. 실패 한 건의 상세 기록

- 연결된 테스트 ID:
- 증상:
- 재현 입력·클릭 순서:
- 기대값과 그 근거:
- 실제값:
- 로그·응답·스크린샷·파일 경로:
- 확인된 원인:
- 아직 확인하지 못한 가설:
- 수정한 파일·내용:
- 재검증한 명령·행동:
- 재검증 기준 버전·시각:
- 재검증 결과: NOT_RUN
- 함께 다시 확인한 영향 범위:
- 남은 위험·미확인 사항:

### 작성 예시 — 형식만 참고

- 테스트 ID: A01
- 기대: 취소 제외 35,000원
- 실제: 취소 포함 44,000원
- 차이: 취소 건 9,000원이 더해짐
- 원인: 상태 필터 누락을 코드에서 확인
- 조치: 승인 조건 필터 적용
- 재검증: **아직 실행 전이면 NOT_RUN**. 실행 후 실제 값과 증거 경로를 추가
- 영향 범위: 전체 합계, 품질 필터, API 응답, 화면, CSV를 필요한 범위에서 다시 비교

## 5. 완료 보고용 요약

- 실제 실행한 범위:
- PASS / FAIL / BLOCKED / NOT_RUN 개수: 미집계
- 핵심 요구사항 충족 근거:
- 수정 후 재검증한 항목:
- 아직 확인하지 않은 것:
- 사용자가 결정해야 할 사항:
- 다음 작업자가 재현할 실행 방법:
- 제출할 코드·데이터·실행 설명의 위치:

**보고 예:** “승인 합계와 부서 필터는 자동 테스트로 확인. 화면 조작과 다운로드는 브라우저에서 확인. 로그인·DB 저장 기능은 이번 예제 범위 밖이며 검증하지 않음.” 실제로 수행한 범위에 맞춰 고쳐 쓰기.
