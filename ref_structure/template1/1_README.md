### 역할이 비슷해 보이는 폴더의 구분

문서·발표·최종 결과물 전용 폴더는 미리 만들지 않습니다. 결과물은 사용자나 업무 요구사항에서 지정한 경로에 저장하고, 별도 지정이 없으면 프로젝트 루트에 용도가 드러나는 파일명으로 저장합니다. `9_temp`는 임시 작업물용으로 사용합니다.

- `0_references`와 `1_research`: 받은 참고자료는 `0_references`, 직접 조사해 작성한 메모와 출처 정리는 `1_research`에 둡니다.
- `0_references`와 `0_references/rawdata`: 요청서·설명 문서는 `0_references`, 계산·분석의 입력 원본은 그 안의 `rawdata`에 둡니다.
- `0_references/rawdata`와 `1_data`: 원본은 `rawdata`에 보존하고, 편집·정제한 사본은 `1_data`에 저장합니다. 결과 재현에 필요하면 `1_data`의 파일이 어느 원본에서 만들어졌는지와 사용한 코드를 연결합니다.
- ~~`3_tests`~~와 ~~`3_evidence`~~: 검사하는 코드와 작은 입력 예제는 ~~`3_tests`~~, 실제 실행·검토 결과는 ~~`3_evidence`~~에 둡니다. `7_VALIDATION.md`에서 대상 요구사항·판정·증거 경로를 연결합니다. ~~`3_tests`~~를 빼더라도 필요한 결과 검토는 수행합니다. (2026-11-05 16:40 KST 대체, 10절 참고)
- `2_src`와 ~~`2_scripts`~~: 최종 기능의 핵심 코드는 `2_src`, 그 결과를 보고서로 만드는 보조 코드는 ~~`2_scripts`~~에 둡니다. 보고서 생성 자체가 제품의 핵심 기능이라면 해당 코드는 `2_src`에 둡니다. (2026-11-05 16:40 KST 대체, 10절 참고)
- ~~`2_scripts`~~와 `9_temp`: 재사용할 보조 코드는 ~~`2_scripts`~~, 버려도 되는 일회성 실험은 `9_temp`에 둡니다. 결과 재생성에 필요한 코드를 임시 파일처럼 삭제하지 않습니다. (2026-11-05 16:40 KST 대체, 10절 참고)

### 9_temp가 필요한 경우

- 필수 폴더가 아닙니다. 작은 업무에서 임시 파일이 생기지 않으면 복사본에서 생략해도 됩니다.
- `working`은 모든 작업물을 뜻할 수 있어, 임시 용도가 드러나는 `9_temp`라는 이름을 사용합니다.
- 버릴 수 있는 보고서 초안, 화면 시안, 일회성 계산 결과처럼 보존 의무가 없는 작업물을 둡니다.
- 원본 데이터, 확정한 가공 데이터, 재실행에 필요한 코드, 검증 증거, 최종 결과물의 유일한 사본은 넣지 않습니다.
- 계속 사용할 파일은 해당 정식 폴더로 옮깁니다. 폴더 이름만 보고 자동 삭제하지 말고, 작업 종료 시 내용을 확인해 정리합니다.

### 기록 문서를 작성·수정할 때의 공통 규칙

1. **필요성 판단:** 목표·제약의 확정이나 변경, 중요한 작업·결정, 새 지식·교훈, 검증 결과, 세션 전환 등 기록이 유용한 상황이면 AI가 먼저 작성을 제안합니다.
2. **구체적인 제안:** 문서명, 새로 작성할지 기존 내용을 수정할지, 담을 핵심 내용과 이유를 짧게 제시합니다. 사용자가 무엇을 승인하는지 알 수 있을 만큼 구체적으로 설명합니다.
3. **여러 문서 일괄 제안:** 한 번 물을 때 여러 문서를 함께 제안해도 됩니다. 문서별 작성 내용을 나열하고, 사용자가 전체 또는 일부만 승인할 수 있게 합니다.
4. **승인 후 실행:** 승인받은 문서와 내용만 작성·수정합니다. 응답이 없거나 일부만 승인된 경우, 승인되지 않은 문서는 변경하지 않습니다. 이후 승인 범위를 벗어나는 내용이 필요하면 다시 제안합니다.
5. **이미 주어진 승인 활용:** 사용자가 특정 문서와 작성·수정 내용을 직접 요청한 경우 그 요청 범위를 승인으로 봅니다. 같은 범위에 대해 재승인을 묻지 않습니다. 일반적인 업무 수행 요청을 기록 문서 전체의 갱신 승인으로 확대 해석하지 않습니다.

## 5. 복사해서 사용하는 순서

1. **원본 `template1` 폴더 전체를 원하는 작업 위치에 복사합니다.**
2. 복사한 폴더 이름을 실제 프로젝트명으로 바꿉니다. 예: `sales_analysis`.
3. 복사본의 `1_README.md`에서 각 요소의 역할과 업무별 조합을 확인합니다.
4. **복사본에서 불필요한 폴더와 빈 MD 파일을 삭제합니다.** 재사용할 원본 템플릿은 그대로 둡니다.

6. 참고자료와 데이터를 배치하고 작업을 시작합니다. 나중에 필요해진 폴더는 다시 추가해도 됩니다.
7. 검토한 결과물을 전달합니다. 추가 기록이 필요하면 대상 문서와 내용을 묶어 제안하고, 승인받은 범위만 갱신합니다.

## 6. 업무 규칙 참고

아래의 코드·인코딩 등은 업무 규칙을 정할 때 참고하는 예시입니다.

### 쉬운 코드와 작업 원칙

- 다른 사람이 이해하고 수정할 수 있는 간단한 코드와 명확한 이름을 사용합니다. 필요 이상으로 추상화하거나 새 도구를 도입하지 않습니다.
- 작업 전 목표·제약·완료 기준과 관련 자료를 확인합니다. 중요한 미정 사항은 질문하고, 영향이 작은 가정은 명시합니다.
- 구현·문서 작성 후 실제 결과를 확인합니다. 수행하지 않은 검증을 완료했다고 기록하지 않습니다.
- 주요 변경이나 새 사실·교훈이 생기면 `3_PROGRESS.md`, ~~`4_KNOWLEDGE_LESSONS.md`~~에 담을 내용을 제안하고 승인 후 정리합니다. (2026-11-05 16:45 KST 통합, 11절 참고)
- 인수인계가 필요하면 `5_HANDOFF.md`의 갱신 내용을 제안하고 승인 후 반영합니다. 다음 세션은 관련 문서와 실제 파일을 확인한 후 이어갑니다.
- 여러 작업을 나눠 맡길 때는 담당 범위·입력·출력·완료 기준을 정하고, 동시에 같은 파일을 수정하는 충돌을 피합니다.

### 인코딩 문제를 줄이는 규칙

- 새 텍스트·Markdown·코드 파일은 프로젝트가 다른 형식을 요구하지 않으면 UTF-8로 읽고 저장합니다.
- 기존 파일은 인코딩·BOM·줄바꿈 형식을 먼저 확인하고 보존합니다. 알 수 없는 파일을 임의로 UTF-8로 해석해 덮어쓰지 않습니다.
- Python 등에서 파일을 읽고 쓸 때 인코딩을 명시합니다. UTF-8 BOM 입력처럼 확인된 형식에 맞춰 처리합니다.
- CSV는 제출 규격과 사용 도구가 요구하는 인코딩을 따릅니다. 모든 CSV에 BOM을 붙이거나 제거하는 식으로 일괄 변경하지 않습니다.
- 터미널 표시 문제와 파일 내용 손상을 구분합니다. 화면에서 깨져 보인다는 이유만으로 원본을 다시 저장하지 않습니다.
- 저장 후 다시 읽어 한글·특수문자·대표 데이터가 유지됐는지 확인합니다. 문서 산출물은 가능한 경우 실제 파일을 열거나 렌더링해 확인합니다.

이 규칙은 오류 가능성을 줄이기 위한 원칙이며, 선언만으로 인코딩 문제가 자동 해결되지는 않습니다.

## 7. HANDOFF와 세션 전환

`3_PROGRESS.md`는 누적 이력, `5_HANDOFF.md`는 **가장 최근의 이어받기 안내**입니다. AI는 인수인계가 필요하다고 판단하면 다음 항목 중 실제로 담을 내용을 제안하고, 승인 후 기록합니다.

1. 지금까지 완료한 것과 실제 파일 경로.
2. 현재 작동하는 범위와 마지막 검증 결과.
3. 중요한 결정사항과 이유. 긴 근거는 해당 문서 위치를 참조.
4. 남은 일과 우선순위, 다음에 바로 할 첫 행동.
5. 알려진 오류·미확인 사항·주의점.
6. 필요한 실행 방법, 작업 디렉터리, 데이터 기준 버전. 비밀키·비밀번호는 기록하지 않음.
7. 마지막 갱신 시점과 실제 파일 상태.

컨텍스트가 가득 차서 중요한 조건을 잃기 전, 또는 단계가 끝나는 시점에는 AI가 인수인계 문서 갱신을 제안할 수 있습니다. 필요하면 진행 이력·검증 기록 등도 함께 제안하되, 문서별 내용을 밝히고 승인을 기다립니다. 고정된 비율이나 “반드시 새 세션”을 규칙으로 삼지 말고 남은 시간·대화 상태·작업 단위를 보고 판단합니다.

새 세션은 `2_PROJECT.md`, `5_HANDOFF.md`를 우선 확인하고 필요한 `3_PROGRESS.md`, ~~`4_KNOWLEDGE_LESSONS.md`~~, 검증 결과를 읽습니다. 문서와 실제 파일 상태가 다르면 차이와 수정할 문서·내용을 제안하고, 승인 후 반영합니다. 경로를 적는 것만으로 자동 세션 연결이 되는 것은 아닙니다. (2026-11-05 16:45 KST 통합, 11절 참고)
