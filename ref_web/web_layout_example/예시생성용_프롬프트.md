서로 다른 웹페이지 레이아웃 예시를 독립 HTML 파일 20개로 만들어줘.

저장 위치:
[저장할 폴더의 절대경로]

목적:
- 실제 서비스를 개발하는 것이 아니라, 화면 디자인과 레이아웃을 비교하는 예시 모음이다.
- 다른 AI나 개발자에게 “이런 화면으로 만들어줘”라고 전달할 참고 파일로 사용할 것이다.
- 각 파일은 하나의 완성된 웹페이지처럼 보여야 한다.

화면 선정:
- 이번에 새로 만들 결과물은 총 20개다.
- 10개는 다양한 분야의 일반 웹사이트·웹앱으로 구성한다.
- 나머지 10개는 회사 내부 업무에 사용할 법한 화면으로 구성한다.
- 구체적인 업종과 화면 유형은 네가 다양하게 선정한다.
- 단순히 업종이나 제목만 다르게 하지 말고, 정보를 보여주는 방식과 주요 레이아웃도 다르게 구성한다.

제작 방식:
1. 반드시 1개씩 순서대로 제작한다.
2. 하나를 만든 뒤, 앞서 만든 화면들과 디자인·레이아웃·주요 구성요소 조합을 비교하고 다음 파일을 만든다.
3. 지정 폴더에 기존 HTML 예시가 있다면 먼저 살펴보고, 기존 화면과도 구성을 비교한다.
4. 색상과 문구만 바꾼 동일한 템플릿을 반복하지 않는다.
5. 버튼·입력창·표 같은 기본 요소는 반복 사용해도 된다. 차이는 전체 배치, 정보의 우선순위, 주요 UI 패턴에서 만든다.
6. 억지로 특이하게 만들지 말고, 실제 서비스에서 사용할 법한 대표적이고 자연스러운 디자인으로 구성한다.
7. 유명 서비스의 일반적인 UI 패턴을 참고해도 된다.
8. 한 페이지의 세로 길이를 모니터 한 화면으로 제한하지 않는다. 필요한 경우 스크롤되는 긴 페이지로 만든다.
9. 매번 사용자 승인을 기다리지 말고 20개까지 진행하되, 진행 상황은 짧게 알려준다.

화면 유형 참고 예시 — 고정 목록 아님:
- 아래 3개는 원하는 구체성과 구성 방식을 설명하기 위한 예시일 뿐이다.
- 그대로 제작하거나 반드시 포함할 필요는 없다.
- 더 적합한 유형을 자유롭게 선정하되, 각 화면의 용도에 맞는 배치와 구성요소를 사용한다.

예시 1. 도시·생활 매거진
- 큰 제목, 대표 기사, 비대칭 편집 그리드와 기사 목록 중심.
- 기사별 중요도에 따라 이미지와 글의 크기를 다르게 배치.

예시 2. 조직도·직원 찾기
- 부서 관계를 보여주는 조직도와 주요 담당자 카드.
- 선택한 직원의 업무·소속·연락처 프로필 패널 배치.

예시 3. 경비 정산
- 왼쪽 영수증, 오른쪽 사용일·금액·계정과목 입력 내역.
- 금액 불일치 표시와 하단 정산 합계 구성.

기술 조건:
- HTML 파일마다 CSS와 필요한 JavaScript를 모두 내부에 포함한다.
- 외부 이미지, 외부 폰트, CDN, 라이브러리, API 등 외부 리소스는 사용하지 않는다.
- 아이콘·일러스트·차트·지도 등은 HTML/CSS 또는 inline SVG로 표현한다.
- 별도 모듈을 설치하지 않는다.
- 사용자가 설치·빌드·서버 실행 없이 HTML을 더블클릭해서 바로 볼 수 있어야 한다.
- React 설치는 필요 없다. HTML/CSS로 실제 웹사이트·웹앱처럼 보이게 구현한다.
- 동작은 필수가 아니다. 탭·접기 등 가벼운 동작은 필요하면 넣어도 된다.
- 실제 로그인·결제·예약·발송·저장 기능은 구현하지 않는다.
- 실제 기능이 없는 화면 예시임을 하단에 짧게 표시한다.
- 화면 문구는 한국어 중심으로 작성하고, 중요한 영어 UI 용어는 유지한다.
- 한국어 Windows에서 글자가 깨지지 않도록 UTF-8 BOM과 charset을 적용한다.
- 사람·회사·문서·금액 등은 가상 데이터를 사용한다.
- 가상 데이터라도 화면 안의 수량·금액·합계·상태는 서로 맞게 작성한다.

저장 조건:
- 파일명에 순서와 화면 용도를 알아볼 수 있게 번호와 설명을 넣는다.
- 예: 01_magazine.html, 02_organization.html
- 각 HTML은 다른 파일 없이 단독으로 열려야 한다.
- 기존 파일은 덮어쓰거나 삭제하지 않는다.
- 파일명이 겹치면 기존 파일과 구분되는 새 이름을 사용한다.

검수:
- 가능한 경우 각 파일을 실제 브라우저에 렌더링해 확인한다.
- 1440px, 768px, 390px 화면 폭에서 글자·요소의 겹침과 페이지 전체의 불필요한 가로 넘침을 점검한다.
- 넓은 표·시간표·조직도는 필요하면 해당 영역 안에서 가로 스크롤하도록 만든다.
- 외부 리소스 의존성, 한글 인코딩, 내부 링크 누락도 확인한다.
- 코드 검사와 실제 브라우저 확인을 구분한다.
- 도구 제한으로 확인하지 못한 부분은 확인했다고 하지 말고 간단히 밝힌다.
