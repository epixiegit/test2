# 테이블 데이터 검토 가이드

## 사용 가이드

검토할 table 형식 데이터와 이 MD를 함께 제공하고, “이 MD 기준으로 데이터를 검토해줘”라고 요청한다.

1. 데이터를 실제로 읽고 아래 체크리스트에서 해당 항목을 선택한다. 도구로 검사할 수 있는 항목은 전체 데이터를 대상으로 계산한다. 일부만 검사했다면 범위와 이유를 밝힌다.
2. **파트 1:** 현상 발견과 실제 문제를 구분한다. 컬럼의 의미·사용 목적에 따라 문제 여부를 판단하고, 정상 표현은 오류 건수에서 제외한다. 근거가 부족하면 확인 필요로 표시한다.
3. **파트 2:** 개수·비율·분포와 후보의 근거를 제시하고, 이상 여부는 사용자가 판단하도록 한다.
4. 원본 데이터는 수정하지 않는다. 앞자리 0, 문자 `NA`, 공백 등 원래 표현을 보존해 먼저 검사한다. 형식 변환은 검사용 사본에 적용하고 원래 값과 비교한다.
5. **원본 데이터와 검사용 값은 마스킹하지 않는다. 보고서에 개인정보를 예시로 인용할 때만 형식 특징을 유지해 마스킹한다.**
6. 폴더명·파일명·이전 대화로 사용 목적을 추론하고 목적 적합성 의견을 제시한다. 추론 근거를 밝히되 사용자가 명시한 목적을 우선하며, 추론만으로 업무 규칙을 만들어 오류를 판정하지 않는다.
7. 수행하지 못한 검사는 **미검토 — 이유**, 적용되지 않는 항목은 **해당 없음 — 이유**로 표시한다. 이상이 없어도 “검사한 항목에서 문제 발견 없음”으로 표현한다.
8. 문제·후보의 컬럼명과 행 위치를 표시하고 헤더 포함 여부를 밝힌다. XLSX는 시트명·셀 주소도 적는다. 발생 건수와 행 위치는 구분한다.

### 보고서 작성 형식

상세 검토보다 앞에 다음 네 항목을 순서대로 작성한다.

1. **파트 1 결론요약:** 문제 유무·규모·필요한 조치.
2. **파트 2 결론요약:** 주요 분석 결과와 사용자가 판단할 부분.
3. **기타 언급해야 할 내용:** 주의점·미검토 범위·판단의 전제. 없으면 “없음”.
4. **최종결론:** 해당 목적에 바로 쓸 수 있는지, 어떤 정리·확인이 필요한지.

앞의 세 항목에서는 중요한 문제·판단 사항마다 **실제 예시 1~2개 → 문제 또는 판단 이유 → 처리·확인 방향**을 함께 적는다. 형식 통일은 변경 전 → 후를 보여준다. 가상 예시는 실제 발견 사례와 구분한다.

> 예: 발주번호 65개 행의 표기를 통일해야 한다. 2행 `po_id`의 `PO 000100` → `PO-000100`으로 바꿔야 다른 표의 같은 발주번호와 연결할 수 있다.

정상 항목은 검사 범위가 드러나도록 묶어 요약하고, 상세 통계·근거는 판단이나 조치에 필요한 경우에만 아래에 적는다. 보고서를 줄이기 위해 체크리스트를 삭제하거나 필요한 검사를 생략하지 않는다.

## 체크리스트

### 파트 1. 보안 / 에러 / 문제 / 정합성

문제가 발견되면 후속 사용 전에 확인하거나 조치해야 하는 부분이다.

#### ① 보안

- [ ] 전달 목적에 불필요한 개인정보·민감정보가 포함되어 있는가?
- [ ] 데이터 내용이나 전달 방식이 제공된 회사 보안 규정에 위배되는가?

#### ② 에러

- [ ] 인코딩 문제로 한글·특수문자가 깨지는가?
- [ ] 사용할 데이터에 `#REF!`, `#VALUE!`, `#DIV/0!` 같은 Excel 오류가 있는가?

CSV에서는 오류 문자열의 존재를 확인한다. 원래 Excel 수식 자체는 CSV만으로 검증할 수 없다.

#### ③ 표 구조·표기 문제

- [ ] 중간에 헤더가 반복해서 등장하는가?
- [ ] 소계·합계 행이 상세 데이터에 섞여 있는가?
- [ ] 완전히 빈 행·열이 있는가?
- [ ] 병합 셀·다단 헤더 때문에 행이나 열의 의미가 불명확한가?
- [ ] 정수·텍스트·단위 표기 등 서로 다른 타입이 섞여 있는 컬럼이 있는가?
- [ ] 앞뒤 공백·줄바꿈·보이지 않는 문자가 있는가?
- [ ] 형식 변경 또는 일치화가 필요한 컬럼이 있는가?
- [ ] 출력 데이터의 한 행이 무엇을 의미하는지 불명확한가?

병합 셀은 XLSX에서 확인한다. CSV에서는 병합 여부를 확정하지 않고, 현재 표의 헤더와 값 배치를 확인한다.

#### ④ 정합성

아래 항목은 해당 업무 기준이 제공된 경우에 검사한다.

- [ ] 필수 항목 또는 특정 조건에서 필요한 값이 빠져 있는가?
- [ ] 있어야 할 날짜·대상·조합의 데이터가 통째로 빠져 있는가?
- [ ] 필수 식별 키가 비어 있거나, 고유해야 하는 키가 중복되는가?
- [ ] 같은 ID에 서로 양립할 수 없는 속성이 연결되어 있는가?
- [ ] 허용 목록에 없는 상태값·분류값·코드가 있는가?
- [ ] 코드·전화번호·이메일 등이 지정된 형식에 맞지 않는가?
- [ ] 시작일 ≤ 종료일 등 날짜의 선후 관계가 정해진 규칙에 맞지 않는가?
- [ ] 수량 × 단가 = 금액 등 정해진 계산 관계가 맞지 않는가?
- [ ] 상태와 관련 값이 업무 규칙상 모순되는가? 예: 완료일이 필수인데 완료 상태에 완료일이 없음
- [ ] 함께 존재할 수 없는 값이 동시에 입력되어 있는가?

### 파트 2. 분석

현황과 후보를 근거와 함께 제시하고, 이상 여부는 사용자가 판단하는 부분이다.

#### ① 빈값·누락 분포

- [ ] 열별·행별 빈값의 개수와 비율을 분석한다.
- [ ] `NULL`, `N/A`, `-`, 공백 등 빈값 표현 후보의 종류와 빈도를 확인한다.
- [ ] 0과 빈값이 사용된 현황을 비교한다.
- [ ] 특정 기간·집단에 누락이 집중되는지 분석한다. 여러 파일을 제공받은 경우 파일별 차이도 확인한다.

빈값으로 집계한 표현과 비율의 분모를 명시한다. `NULL`, `N/A`, `-`, 0 등을 근거 없이 같은 의미로 취급하지 않는다.

#### ② 중복·반복 패턴

- [ ] 같은 표에서 동일한 행이 얼마나 반복되는지 확인한다. 여러 파일을 제공받은 경우 파일 간 반복도 확인한다.
- [ ] 같은 대상의 서로 다른 표기 후보를 찾는다.
- [ ] 반복 기록을 추출하고, 수정 이력·분할 거래·반복 측정 여부를 판단할 정보를 보여준다.

#### ③ 값의 분포·단위

- [ ] 단위와 규모의 종류·빈도를 확인한다. 예: 원·천 원, g·kg
- [ ] 다른 값들과 크게 차이 나는 이상치 후보와 선정 근거를 보여준다.
- [ ] 특정 값에 대한 집중도와 기본값 반복 현황을 분석한다. 기본값이 무엇인지 모르면 반복 빈도가 높은 값을 보여준다.

#### ④ 활용 필요성

- [ ] 후속 업무의 목적이 제공된 경우, 불필요할 수 있는 일반 컬럼을 제시한다.
