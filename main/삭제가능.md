### ① 구현 전에 해결할 문제를 확정하기

- 누가 어떤 업무에서 어려움을 겪는가?
- 어떤 결과가 나오면 해결됐다고 볼 수 있는가?
- 반드시 지켜야 할 조건은 무엇인가?
- 자료만으로 확정할 수 없는 것은 무엇인가?

실무 AI와의 질의응답도 질문 수를 늘리기보다 이러한 불확실성을 줄이는 데 목적을 둡니다.

### ② AI에게 작업 범위와 제약을 함께 주기

> **직접 만든 요청 예시**  
> 주문 집계가 틀리는 원인을 먼저 찾아줘.  
> 취소 주문 제외 규칙과 기존 API 응답 형식은 유지해.  
> 수정할 파일과 영향 범위를 설명한 뒤 최소 범위로 수정하고, 정상·취소·빈 데이터 사례를 검증해줘.

긴 프롬프트 자체보다 해야 할 작업과 유지할 조건이 분명한지가 중요합니다.

### ③ 완료 보고 대신 검증 증거 확인하기

1. 작은 입력에서 기대값을 직접 정합니다.
2. 실제 출력과 비교합니다.
3. 예외와 실패 조건도 확인합니다.
4. 수정 후 같은 검증을 다시 실행합니다.

AI가 완료했다고 말한 사실과 실제 결과의 정확성을 구분합니다.

### ④ 진행 중 판단을 바꾼 이유 남기기

> **기록 예시 — 해당 과제 조건에 맞을 때만 적용**  
> 남은 시간에 비해 로그인 기능의 구현 부담이 커서 제외했다. 문제에서 요구하는 사용자 구분은 제공 데이터의 사용자 ID로 충족한다.

판단 근거는 우선순위 조정의 증거가 됩니다. 문서의 개수나 분량 자체를 늘리는 것이 목적은 아닙니다.

### ⑤ 결과물의 구조와 한계를 이해하기

- 입력부터 결과까지 어떤 순서로 처리되는가?
- 핵심 계산·판단 규칙은 어디에 있는가?
- 왜 이 구조와 도구를 선택했는가?
- 어떤 조건에서 잘못되거나 작동하지 않을 수 있는가?

### ⑥ 사후 답변을 실제 구현과 맞추기

구현하지 않은 기능, 실행하지 않은 테스트, 검증하지 않은 정확도를 답변에 넣지 않습니다. **무엇을 만들었는지 → 왜 그렇게 했는지 → 어떻게 확인했는지 → 무엇이 남았는지**를 자신의 작업에 근거해 설명하는 연습이 필요합니다.

- 민감정보·보안 위험 관리

- 목표·제약의 명확한 정의
- 작업 분해와 AI 위임
- 방향·우선순위 조정
### ③ 인지

**원리와 한계를 이해하는가?**

- 구조 선택 이유 설명
- 실제 구성·동작 이해
- 한계·실패 조건 예측

### 직무별로 보는 AI 활용 역량

- **개발:** AI로 구현하면서 시스템의 규칙과 안전성을 지키는 능력.
- **기획:** AI에 요청하기 전에 해결할 문제를 정의하는 능력.
- **분석:** AI의 결론에서 근거와 추측을 구분하는 능력.
- **회계:** 자동화할 작업과 사람이 판단할 작업을 구분하는 능력.
- **HR:** AI 제안을 조직·팀의 상황에 맞게 판단하는 능력.
- **전략:** 여러 선택지 중 무엇을 고를지 기준을 세우는 능력.

- **좋은 사용:** 실패 원인·수정 범위를 먼저 확인 → 기존 인증 방식과 API를 유지하도록 제약 지정 → 정상·실패 경로를 테스트하고 결과 확인.
- **나쁜 사용:** 구체적인 범위 없이 모두 위임 → 기존 인증 방식도 임의로 변경하도록 허용 → 테스트 없이 완료 보고만 확인.
